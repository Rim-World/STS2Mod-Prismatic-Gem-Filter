# 007 判定依据选棱彩宝石持有状态

- 状态：已接受
- 日期：2026-11-15
- 当时的项目版本：0.0.2（已部署，未发版）
- 相关文件：`1.PRD/001-项目初期需求.md`（RQ-002、RQ-005、RQ-012）、`3.DOCS/010-E-发牌调用点与跨界来源.md`、`4.ADR/001-在候选牌枚举处统一过滤.md`

## 背景

[ADR-001](001-在候选牌枚举处统一过滤.md) 把生效条件写成三条并列，第一条是「玩家持有棱彩宝石」。0.0.2 的实现没有这一条。`2.PLANS/002-M-最小工程.md` 的「判定顺序」一节给出的理由是：不持有棱彩宝石时候选只含本职业卡池的牌，池门控会把它们全部保留，过滤成为空操作。

这个理由依赖一个前提：未持有棱彩宝石时，没有别的来源加宽卡池。该前提不成立。

`3.DOCS/010-E-发牌调用点与跨界来源.md` 记录了四条不依赖棱彩宝石、却能把别的职业卡池写进候选的来源：

| 来源 | 类 | 依据 |
|---|---|---|
| 万花筒遗物 | `Kaleidoscope` | `Kaleidoscope.cs:40` 取三个他职业池，`:44` 带 `NoCardPoolModifications` |
| 海玻璃遗物 | `SeaGlass` | `SeaGlass.cs:82-84` 用单个指定角色池 |
| 色彩哲学家事件 | `ColorfulPhilosophers` | `ColorfulPhilosophers.cs:42` 筛掉本职业池，`:57-59` 构造他职业池的 options |
| 角色卡修正器 | `CharacterCards` | `CharacterCards.cs:56` 把指定角色池并进候选 |

0.0.2 对这四条来源同样会排除名单内的牌，与 RQ-005 冲突。用户在 2026-11-15 19:28 指出这一点，并要求把判定依据改回「是否持有棱彩宝石」。

## 决策

判定依据取「本次发牌的玩家是否持有棱彩宝石遗物」。模组在补丁里读 `Player.Relics`，判定是否含 `PrismaticGem`。

另设一个模式开关，默认取上句的判定；切到另一个取值时改用「候选里是否出现玩家职业卡池之外的牌」作判据，即 0.0.2 的现有行为。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 保持 0.0.2 的单一判据 | 违反 RQ-005，万花筒、海玻璃、色彩哲学家会被无端删牌 |
| 判据改成「棱彩宝石是否改写了这次 options」 | 需要复刻 `PrismaticGem.ModifyCardRewardCreationOptions` 的四道早退，且 `WithCardPools` 就地改写、无法区分是谁改的。实现比读遗物复杂，鲁棒性更差 |
| 判据改成「`options.Flags` 是否含 `IsCardReward`」 | 会把万花筒与海玻璃一起排除，但 RQ-002 明确要求持有棱彩宝石时这两处也要过滤 |
| 不做开关，直接改成只读遗物 | 用户要求保留「任何跨界都过滤」作为一种可选行为 |

## 后果

- 获益：RQ-005 与 RQ-002 同时成立。持有棱彩宝石时，万花筒与海玻璃的跨职业候选照样过滤；不持有时，四条跨界来源保持原样。
- 代价：模组新增一处对游戏类型的依赖，`MegaCrit.Sts2.Core.Models.Relics.PrismaticGem`。三版都存在该类，声明位置在 `PrismaticGem.cs:11`（三版行号相同）。
- 代价：判定从「看候选」变成「看玩家状态」，补丁读到的 `Player` 必须是对应发牌的玩家。`GetPossibleCards` 的入参就是该玩家，满足要求。
- 下游规则：模式取值必须持久化在玩家配置档内，游戏重启后保持。条款见 `6.SPEC` 的 SP-017。
- 下游规则：`CardFilter.Apply` 仍保持纯函数，不读玩家状态。遗物判定在拦截层完成。
