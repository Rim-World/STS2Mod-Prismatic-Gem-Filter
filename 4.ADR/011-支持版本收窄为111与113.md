# 011 支持版本收窄为 0.111 与 0.113

- 状态：已接受
- 日期：2026-11-17
- 项目版本：0.0.10（开发中，未发版）
- 相关文件：`1.PRD/001-项目初期需求.md`（RQ-004、RQ-012、RQ-013）、[ADR-002 三版本交付形态](002-三版本交付形态.md)、[ADR-008 判据复刻棱彩宝石的早退集合](008-判据复刻棱彩宝石的早退集合.md)、[DOCS/008-E 三版本API对照](../3.DOCS/008-E-三版本API对照.md)

## 背景

0.0.9 及以前同时服务 0.107.1、0.111.0、0.113.1，见 ADR-002。多支持一个版本的成本落在两处：运行期判据要复刻一条 0.107.1 独有的早退（ADR-008 第 4 条），每次核对要读三套反编译。

2026-11-17 用户说明：正式版已推进到 0.111，不再需要兼容 0.107；只保留 0.111 与 0.113 两个版本。用户自行降级到 0.111 做实测。

两个受支持版本的游戏侧事实：`PrismaticGem.cs` 与 `CardCreationOptions.cs` 在 0.111 与 0.113.1 之间逐字节相同，见 DOCS/008-E，本轮再次比对确认。0.107.1 独有的 `CustomCardPool` 属性在 0.111 起不存在。

## 决策

本模组只支持 0.111.0 与 0.113.1。`mod_manifest.json` 的 `min_game_version` 写 `0.111.0`。

运行期判据由五条合取改为四条：玩家遗物含 `PrismaticGem`；`IsCardReward` 置位；`NoCardPoolModifications` 未置位；卡池不全为无色。删除「卡池非空」一条。

删除依据：`GetPossibleCards` 是 `CardPools.SelectMany(...)`。卡池为空时它必然返回空集合，后置补丁在候选计数处已经返回，该条在任何受支持版本上都不可达。ADR-008 已经写过「在 0.111 与 0.113.1 上卡池为空的选项不产生候选，本条自然不成立」。

其余交付形态不变：一个程序集、一个安装目录、一个清单。编译基线仍是本机的 0.113.1 程序集。0.111 运行期由 RitsuLib loader 选中 `compat/0.111.0` 分支。

## 备选方案

**保留 0.107.1 支持。** 否决。用户明确不再需要；多一个版本就多一条 0.107 专用判据与一轮核对。

**把「卡池非空」判据留在代码里。** 否决。该条在受支持版本上不可达，留下只会让读者以为还有 0.107 分支。删除后行为不变。

**为 0.111 单独编译一个变体。** 否决。两版的 `PrismaticGem` 与 `CardCreationOptions` 相同，运行期要用的成员签名相同，单一程序集继续成立。

## 后果

获益：受支持版本与正式版一致；运行期判据与两个受支持版本的原版行为逐条对应，不再带历史分支。

代价：0.107.1 玩家无法加载本模组，`min_game_version` 会挡下。0.111 的加载与行为仍需用户实测，本机只有 0.113.1 的程序集。

下游规则：

1. 判据改动只对照 0.111.0 与 0.113.1 两套反编译。
2. RQ-013 的「三版本等价」验收收窄为「两版本等价」。
3. 分组表仍按 0.113.1 生成。0.111 缺的卡牌标识不会命中，不影响结果。
4. `min_game_version` 写 `0.111.0`，不得再回退到 `0.107.1`，除非重新走一遍取证。
