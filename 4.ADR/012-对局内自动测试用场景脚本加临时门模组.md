# 012 对局内自动测试用场景脚本加临时门模组

- 状态：已接受
- 日期：2026-11-17
- 项目版本：0.0.10
- 相关文件：`8.TEST/0.0.10/AutoSlayGate/`、`8.TEST/0.0.10/场景-卡牌奖励过滤.txt`、`3.DOCS/017-T-AutoSlayer场景测试接入.md`

## 背景

对局内发牌行为此前只能由用户手动开一局观察。验收用例多为「某个开关打开后，某类牌在奖励里出现次数为 0」，需要可重复、可留档的取样方式。

游戏自带两套自动化设施，都在 `MegaCrit.Sts2.Core.AutoSlay` 命名空间下：AutoSlayer（自动打完整局）与 ScenarioRunner（按脚本走一局）。两者在 `NGame.cs:698`、`NGame.cs:702` 都要求 `IsReleaseGame()` 返回 false，而 `NGame.cs:770` 把返回值写死为 true。父级 `AGENTS.md` 已记录这一点与解法。

约束来自 `AGENTS.md`：探针与测试代码不得留在项目源码与成品中。

## 决策

对局内验证使用 ScenarioRunner 场景脚本，配一个临时门模组。门模组只做两件事：把 `NGame.IsReleaseGame` 的返回值改成 false，在候选集合与发牌结果处挂日志探针。门模组的源码放在 `8.TEST`，测试期间部署到游戏 `mods/` 目录，测试结束后移入回收站。正式模组的代码不为测试做任何改动。

## 备选方案

**在正式模组里加环境变量开关，需要时才翻转 `IsReleaseGame`。** 否决：测试代码会进成品，违反 `AGENTS.md` 的「测试代码必须从源码与成品去除干净」。

**用 `--autoslay` 跑完整局。** 否决：单局上限 25 分钟；角色、遗物、路线都不可控；要拿到棱彩宝石得靠运气，无法稳定复现。

**继续人工实测。** 否决：每轮只能打一两场，统计口径（如 1000 次发牌）永远跑不完，而且没有可以留档的候选集合快照。

**外部 UI 自动化（模拟点击）。** 否决：无头模式没有窗口；场景脚本已经能直接调用控制台命令，不必绕界面。

## 后果

好处：一次运行约 90 秒，能拿到过滤前后的完整候选标识清单，可以逐组核对；同一种子可复现；日志可以留档。

代价与必须遵守的规则：

- 每次对局内验证都要先部署门模组、跑完再回收，多两个手工步骤。
- 场景角色写死铁甲战士（`ScenarioRunner.StartRunAsync`），其他职业只能靠预置修正器或改脚本以外的办法，本轮没有做。
- 场景的 `ApplyPreflight` 会改真实进度：关闭首次弹窗、解锁四个职业的 epoch、改写 `FastMode`。测试前必须确认存档已备份。
- 探针补丁的优先级依赖实测：后置补丁数值大的先执行，探针要排在过滤之后必须用比默认 400 更小的值。
- 不覆盖界面渲染：无头模式不画界面，设置页、豁免页、三种语言仍需目视验证。
- 门模组不得进入 `9.SRC`、不得进入发布包；每次测试后要确认游戏 `mods/` 目录里已经没有它。
