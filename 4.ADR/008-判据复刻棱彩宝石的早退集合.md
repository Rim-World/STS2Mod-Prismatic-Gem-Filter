# 008 判据复刻棱彩宝石的早退集合

- 状态：已接受
- 日期：2026-11-15
- 当时的项目版本：0.0.2（已部署，未发版）
- 相关文件：`1.PRD/001-项目初期需求.md`（RQ-002、RQ-012、RQ-013）、`3.DOCS/010-E-发牌调用点与跨界来源.md`、`4.ADR/007-判定依据选棱彩宝石持有状态.md`

## 背景

[ADR-007](007-判定依据选棱彩宝石持有状态.md) 把判据定为「玩家是否持有棱彩宝石」。查清原版作用面后，这个判据不够。

`3.DOCS/010-E` 的「原版棱彩宝石的作用面」一节记录了机制：钩子 `ModifyCardRewardCreationOptions` 只有三处调用点，且棱彩宝石自己有四道早退。持有遗物是必要条件，不是充分条件。玩家持有棱彩宝石时遇到万花筒、海玻璃、色彩哲学家，宝石并没有加宽那次发牌。

用户于 2026-11-15 20:33 明确要求：过滤范围必须严格等于原版会被棱彩宝石影响的范围，三个版本都是如此。

三版本对照时又发现一处版本差异，见 `PrismaticGem.cs` 逐行对照：

| 版本 | 早退条数 | 差异 |
|---|---|---|
| 0.107.1 | 5 | 多一条 `options.CustomCardPool != null` |
| 0.111 | 4 | 与 0.113.1 逐字节相同 |
| 0.113.1 | 4 | 基准 |

0.107.1 的 `PrismaticGem.cs` 53 行，0.111 与 0.113.1 都是 48 行，后两者 SHA-256 相同。

## 决策

判定按下列五条合取，全部成立才过滤：

1. 玩家遗物里有 `PrismaticGem`。
2. `options.Flags` 不含 `NoCardPoolModifications`。
3. `options.Flags` 含 `IsCardReward`。
4. `options.CardPools.Count` 不为 0。
5. `options.CardPools` 不全为 `IsColorless`。

第 4 条就是 0.107.1 那条 `CustomCardPool` 早退的等价写法。依据：0.107.1 的 `CardCreationOptions.cs:90-96` 里，自定义池构造器不填 `_cardPools`，且 `:206` 的 `WithCardPools` 会把 `CustomCardPool` 置空。所以「卡池为空」与「用的是自定义池」互为充要。在 0.111 与 0.113.1 上该属性已不存在，卡池为空的选项不产生候选，本条自然不成立。

两个枚举值在三版完全一致：`NoCardPoolModifications = 0x10`、`IsCardReward = 0x80`，见各版 `CardCreationFlags.cs`。`CardPoolModel.IsColorless` 在各版都是第 67 行的抽象属性。

开关的第二个取值仍按「候选里出现玩家职业卡池之外的牌」判定，不看遗物，见 SPEC 的 SP-019。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 只判「持有棱彩宝石」（ADR-007 的写法） | 持有宝石时会把万花筒、海玻璃、色彩哲学家发出的牌一并删掉，超出原版作用面 |
| 用反射检测 `CustomCardPool` 属性是否存在 | 能在三版上都正确，但多一处按属性名匹配的运行期探测，且属性缺失时静默退化。第 4 条的空卡池等价写法不需要反射 |
| 三版本各编译一份 | 与 [ADR-002](002-三版本交付形态.md) 的单包交付冲突 |
| 判据按版本写死分支 | 需要运行期识别版本号，多依赖一处版本信息；用等价条件可以完全避开 |

## 后果

- 获益：过滤范围与原版作用面逐条对齐，三个版本同一份代码。万花筒、海玻璃、色彩哲学家、垃圾堆、普通商店、飞溅、恋人一律不受影响。
- 获益：判据只读 `CardCreationOptions` 的公开成员与玩家遗物，不依赖内部状态。
- 代价：判据有五个条件，比「候选是否被加宽」复杂。这是为了与游戏保持一致而付的复杂度。
- 代价：`Core.cs` 的判定函数必须缓存遗物查询结果之外的东西。遗物列表每次现查，不做缓存，避免拾取遗物后失效。
- 下游规则：判定在拦截层完成，`CardFilter.Apply` 保持纯函数。规则见 SDD 的依赖约束。
- 下游规则：模式开关的第二个取值不得复刻这五条，只用「候选出现他职业牌」。条款见 SPEC 的 SP-019。
