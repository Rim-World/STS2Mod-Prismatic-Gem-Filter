# 014 豁免按卡牌跨组同步

- 状态：被 ADR-015 取代
- 日期：2026-11-18
- 项目版本：0.0.12
- 相关文件：`9.SRC/src/ExclusionTable.cs`、`9.SRC/src/ModSettings.cs`、`9.SRC/src/FilterIndex.cs`、[ADR-004](004-豁免在构建索引时扣除.md)、[RQ-022](../1.PRD/001-项目初期需求.md)、[SP-013](../6.SPEC/001-过滤行为规范.md)
- 取代说明：0.0.13 起分组开关与豁免开关合并为同一份卡牌状态，见 [ADR-015](015-筛选状态按卡牌唯一记录.md)。本文的「豁免按卡牌记录」仍有效；「分组开关保持独立」已被 ADR-015 废止。

## 背景

0.0.4 起豁免按「分组标识:卡牌标识」存储。原因之一是 `BIG_BANG` 同时属于铸剑与星，当时的设计允许玩家在一组保留、另一组排除。规则见 ADR-004 与 SP-013。

0.0.12 前，设置页对同一张跨组卡显示两个独立开关。玩家关掉其中一个，另一个不变。用户 2026-11-18 反馈：这违反了「同一张牌的状态应当一致」的设计要求。

当前跨组卡只有两张：

| 卡牌 | 分组 |
|---|---|
| `BIG_BANG`（大爆炸） | 铸造、辉星 |
| `THE_SMITH`（铸剑者） | 铸造、辉星 |

## 决策

豁免按卡牌记录，不按分组记录。豁免清单的元素是裸卡牌标识，例如 `BIG_BANG`。`ExclusionTable.IsDefaultExempt` 与 `SettingsSnapshot.IsExempt` 都只接收卡牌标识。

设置页中，同一张牌无论出现在几个分组，都使用同一个 `CardBindings[entry]` 绑定。任一豁免页的开关改变后，所有包含该卡的豁免页看到同一状态。

分组开关保持独立。某卡是否被排除，仍由「至少一个处于勾选状态的可见分组包含该卡，且该卡未被全局豁免」决定。

## 备选方案

**保留分组键，写一处时同步写其他组。** 否决。旧存档里可能已有互相矛盾的值，读入后仍要额外合并；而且数据模型继续允许分歧，后续任何新入口都可能再次写歪。

**把跨组卡从其中一个分组移除。** 否决。两个分组都准确描述了这张牌；移走会让某个分组的名单不完整，也会改变分组张数。

**关掉一个分组时自动关闭另一个分组。** 否决。分组开关表达的是「排除这一类」，不是「排除这张牌」。把分组开关耦合成卡牌开关会破坏现有语义。

## 后果

获益：同一张牌的豁免状态只有一处来源；跨组页面的开关自动同步；默认豁免清单不再需要为 `BIG_BANG` 写两条。

代价：设置架构版本由 3 升到 4，旧档首次启动整份重置。旧的分组前缀键全部失效，不能增量迁移。分组页不再允许「这组保留、那组排除」的配置。

下游规则：

1. 豁免清单只存卡牌标识，不得再拼分组前缀。
2. 新增跨组卡时，不需要为它在多个分组各写一条默认豁免。
3. 分组开关与豁免开关是两层状态，不得互相写入。
4. 任何读豁免的地方只问卡牌标识；需要分组上下文的地方不得自行拼键。
