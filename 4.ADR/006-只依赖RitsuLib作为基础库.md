# 006 只依赖 RitsuLib 作为基础库

- 状态：已接受
- 日期：2026-11-15
- 项目版本：0.0.1（开发中，未发版）
- 相关文件：[DOCS/006-R 基础库选型调研](../3.DOCS/006-R-基础库选型调研.md)、[ADR-002 三版本交付形态](002-三版本交付形态.md)、[SPEC SP-007、SP-011、SP-012](../6.SPEC/001-过滤行为规范.md)

## 背景

本项目的全部工作是改一条发牌链路，不新增卡牌、遗物、角色或场景。需要基础库解决的问题只有四件：设置界面、持久化、本地化、补丁失败降级。

项目已经确定要支持 0.107.1、0.111.0、0.113.1 三个游戏版本（RQ-004）。三个版本的 `CardCreationOptions` 存在 API 差异，其中 0.107.1 有 `CustomCardPool`，0.111.0 起改为 `WithFilter`。这个差异落在本项目的补丁点所在类型上。

两个候选库都是 MIT 许可、都在活跃维护。BaseLib v3.4.8 发布于 2026-11-12，RitsuLib v0.6.13 发布于 2026-11-14。

取证见 [DOCS/006-R](../3.DOCS/006-R-基础库选型调研.md)。

## 决策

本项目在编译期与运行期只依赖 RitsuLib，不依赖 BaseLib。RitsuLib 作为硬依赖写在 `mod_manifest.json` 中，未安装时模组不加载。

## 确认记录

- 2026-11-15 16:56：用户确认接受硬依赖形态，即玩家必须安装 RitsuLib。

## 备选方案

**只依赖 BaseLib。** 否决。BaseLib 的主能力面是内容添加，本项目不需要。它没有面向上层模组的补丁框架与补丁降级机制，SP-011 要自己实现。它靠单一 DLL 反射回退兼容旧签名，不提供版本门控工具。它的发布包附带第二个 mod `BaseLibCompatibilityHelper`，玩家安装链从 2 个 mod 变成 3 个。

**同时依赖两个库。** 否决。两个库都提供设置页与持久化，同时启用会出现两套设置入口与两套存档目录。多装一个 BaseLib 对本项目没有功能贡献，只增加冲突面。

**不依赖任何库。** 否决。设置界面需要把自己的页面注入游戏菜单并自绘 Godot 控件，这是最容易随游戏版本失效的部分。省下的依赖成本换成长期的界面维护成本，与「不重复造轮子」的目标相反。

**把 RitsuLib 设为软依赖。** 暂不采用。软依赖要求全部调用走反射或类型探测，每个版本都要处理「有 RitsuLib」与「没有 RitsuLib」两条路径，测试组合翻倍。同类模组 SplashExclusion 采用硬依赖。若后续需要降低安装门槛，另开 ADR 重新决策。

## 后果

**获益**

- 补丁降级直接复用 RitsuLib 的 `ignoreIfMissing` 与 `IsCritical`，对应 SP-011。
- 设置页与持久化直接复用，对应 RQ-006、SP-007、SP-015。
- 本地化复用 `I18N`，不需要自己合并游戏文本表。
- RitsuLib 按 API 版本提供 0.107.1、0.111.0、0.113.0 三套模块与变体包，运行时按宿主版本自动选择（`components/loader/BundleLayout.cs:44-48`）。这覆盖 RQ-004 的三版本要求，且与 ADR-002 的交付形态可以合并处理。

**代价**

- 玩家必须安装 RitsuLib，安装清单从 1 项变为 2 项。
- 本项目随 RitsuLib 的版本节奏更新，其发布频率约为每天一次。
- RitsuLib 含遥测与更新检查两个联网子系统。两者都受开关或同意控制，但需要在本项目 README 与工坊说明中如实披露。
- RitsuLib 自身补丁面较大，覆盖存档、联机同步与 UI。本项目的补丁越窄，冲突面越小。

**下游必须遵守的规则**

1. `mod_manifest.json` 的 `dependencies` 必须声明 `{"id": "STS2-RitsuLib"}`，并写明最低版本。
2. 源码不得引用 `BaseLib` 命名空间，不得依赖 `BaseLib.dll`。
3. 补丁必须按 RitsuLib 的 `IPatchMethod` 声明，禁止在初始化入口直接调用 `Harmony.PatchAll`。
4. 设置项标识一经发布不得改名，改名会丢玩家的已保存值。
5. 三个版本的构建分别引用对应的 RitsuLib 兼容包，发布说明必须写明玩家应安装的 RitsuLib 变体包版本。
6. README 与工坊说明必须写明遥测与更新检查来自 RitsuLib，并给出关闭路径。
