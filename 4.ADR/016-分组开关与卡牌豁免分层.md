# 016 分组开关与卡牌豁免分层

- 状态：已接受
- 日期：2026-11-19
- 项目版本：0.0.14
- 相关文件：`9.SRC/src/ModSettings.cs`、`9.SRC/src/FilterState.cs`、`9.SRC/src/FilterIndex.cs`、`9.SRC/src/ExclusionTable.cs`、[ADR-015](015-筛选状态按卡牌唯一记录.md)、[RQ-024](../1.PRD/001-项目初期需求.md)、[SP-031](../6.SPEC/001-过滤行为规范.md)

## 背景

0.0.13 把分组开关与卡牌豁免合并为一个 `Filtered` 集合。分组开关是集合的聚合视图与批量命令，没有独立落盘状态。

用户 2026-11-19 更正了要求：

1. 分组开关与单卡豁免名单是两层独立状态。
2. 一张牌在 A 组被豁免，在 B 组也必须豁免；在 A 组可过滤，在 B 组也可过滤。状态跨组共享，但不等于分组开关与单卡状态共用一份数据。
3. 组关闭时，本组贡献显示 `0/13`；如果组内跨组牌仍被其他已开启组过滤，追加一句 `本组仍有 1/13 在其他组被过滤`。
4. 只要有一组开启且该卡未豁免，该卡就应被过滤。
5. 旧设置重置为默认值。

0.0.13 的 `SetGroup` 还有一个具体缺陷：关闭一组时直接移除该组全部成员，不会因另一组仍开启而加回跨组牌。这会违反第 4 条。

## 决策

持久化两份独立来源：

```csharp
public Dictionary<string, bool>? Groups { get; set; }
public List<string>? Exemptions { get; set; }
```

- `Groups`：每个分组一个开关。缺键时取 `CardGroup.DefaultEnabled`。
- `Exemptions`：裸卡牌标识的全局豁免名单。组开关不得写入此字段，单卡开关不得写入 `Groups`。

实际过滤池不落盘，只作内存缓存：

```text
Pool = ⋃ 已开启且当前版本可见的分组（成员） − 全局豁免牌
```

过滤池由 `FilterState.BuildPool` 从两份来源重算。禁止在组开关、单卡开关或其他入口增量维护第三份持久化池。

分组说明：

- 主行显示本组自身贡献：组开启时为“成员数 − 本组豁免数”，组关闭时为 0。
- 组关闭且组内至少有成员被其他开启组过滤时，追加“本组仍有 x/y 在其他组被过滤”。
- 单卡页面仍显示全局豁免状态，与组开关无关。

设置架构版本由 5 升到 6。旧档首次启动整份重置；不迁移 0.0.13 的 `Filtered`，因为旧数据无法区分“组关闭”与“单卡豁免”。

## 备选方案

**把总过滤池作为第三份持久化状态，按用户的增量算法维护。** 否决。增量算法在数学上等价于并集减豁免，但需要覆盖组开关、单卡开关、启动、重置、版本切换与跨组加回等全部路径。任何一条路径漏写都会产生漂移，且“先移除再按其他组加回”会产生可见的中间状态。当前规模只有 15 组、180 行，全量重算的成本可忽略。

**继续使用 0.0.13 的单一 `Filtered` 集合，分组开关保持批量命令。** 否决。关闭一组会清除单卡状态，且跨组牌可能因一组关闭而错误地不再被过滤。用户明确要求两层独立。

**组关闭时把全部成员从池中移除，不按其他开启组加回。** 否决。这违反“只要有一组开启且该卡未豁免就过滤”。用户描述的加回步骤是对的；实现上用全量重算得到同一结果，更稳。

**把分组说明显示为组内成员的实际全局过滤数。** 否决主行采用该口径。用户要求组关闭时主行显示 `0/13`。因此主行表示本组贡献，跨组造成的实际过滤单独一行说明。

## 后果

获益：

- 分组开关与单卡豁免各有唯一来源，互不写入。
- 同一张牌在所有分组页面共享一个豁免状态。
- 跨组牌不会因关闭其中一组而失去其他组的过滤。
- 过滤池只由两份来源计算，不会出现第三份状态漂移。
- 组关闭时仍能看到本组贡献为 0，以及跨组造成的实际过滤数。

代价：

- 设置架构升到 6，旧档首次启动重置。
- 组关闭时主行显示的 0 不是组内所有成员的全局实际状态；跨组影响需要看第二行。
- 每次设置写入后全量重算过滤池。规模小，成本可接受。

下游必须遵守的规则：

1. 不得新增按分组存储的单卡豁免键。
2. 分组开关写入不得修改 `Exemptions`。
3. 单卡开关写入不得修改 `Groups`。
4. 实际过滤池只能由 `FilterState.BuildPool` 生成，不得持久化。
5. 组说明主行显示本组贡献；跨组过滤数只在本组关闭时追加。
6. 实际发牌仍受总开关、判定模式、本职业卡池门控与空结果回退覆盖，这些不是第二份卡牌状态。
