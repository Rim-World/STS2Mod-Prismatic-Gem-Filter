# 015 筛选状态按卡牌唯一记录

- 状态：已接受
- 日期：2026-11-18
- 项目版本：0.0.13
- 相关文件：`9.SRC/src/ModSettings.cs`、`9.SRC/src/FilterState.cs`、`9.SRC/src/CardStateDefaults.cs`、`9.SRC/src/FilterIndex.cs`、[ADR-014](014-豁免按卡牌跨组同步.md)、[RQ-023](../1.PRD/001-项目初期需求.md)、[SP-031](../6.SPEC/001-过滤行为规范.md)

## 背景

0.0.12 的数据模型有两层状态：

1. `SettingsModel.Groups` 保存每个分组的勾选状态。
2. `SettingsModel.Exemptions` 保存每张牌的豁免状态。

排除规则是「至少一个处于勾选状态的可见分组包含该卡，且该卡未被全局豁免」。这使同一张跨组卡的实际状态取决于分组层与卡牌层的组合。

用户 2026-11-18 20:22 指出：分组开关与豁免开关都应当同步；一张牌的豁免状态和实际过滤状态都应当唯一且同步。

现有模型无法满足这一点。举例：`THE_SMITH` 同属铸造与辉星，两个分组默认勾选。玩家关掉铸造组，铸造组豁免页显示保留 `THE_SMITH`；辉星组仍勾选，实际发牌仍排除 `THE_SMITH`。同一张牌在一个页面是保留，在另一个页面是排除。卡牌层的豁免状态与分组层的实际结果不一致。

`BIG_BANG` 与 `THE_SMITH` 是当前仅有的两张跨组卡。名单生成脚本已限制跨组重复只能是这两张，见 SP-014。

## 决策

唯一持久化的筛选状态是「被排除的卡牌标识集合」，落盘字段为 `SettingsModel.Filtered`。每张卡只有两种状态：

- 在集合内：排除。
- 不在集合内：保留。

分组开关不再是第二份状态。它是同一个集合的聚合视图与批量命令：

- 读取：本组至少有一张成员在 `Filtered` 内时显示为开；全部成员都不在时显示为关。
- 写入开：把本组全部成员加入 `Filtered`。
- 写入关：把本组全部成员移出 `Filtered`。

豁免页的每张卡开关是同一集合的单卡视图：

- 勾选「豁免」：把该卡移出 `Filtered`。
- 取消「豁免」：把该卡加入 `Filtered`。

分组开关与豁免开关都通过同一个父绑定 `FilteredBinding` 的投影实现。RitsuLib 的刷新拓扑会沿投影关系把父绑定的变更传播到所有分组开关与所有卡牌开关，因此一个页面改动后，其他页面的同一状态会刷新。

分组说明显示「已排除 x/y」。当 `0 < x < y` 时开关仍为开，但说明行会暴露部分保留。用户关闭该组会保留全组，再打开会排除全组。

默认值由分组默认状态推导：

```
Filtered_default = ⋃ 默认勾选的分组（成员） − 显式默认豁免
```

显式默认豁免仍为 SP-021 的 10 张牌。默认集合按 `CardGroupTable.Rows` 全表与 `CardGroups.All` 的默认值计算，包含当前游戏版本隐藏的愚者卡。不能直接遍历 `CardGroups.All` 的成员：0.111 的 `All` 已剔除愚者成员，会让玩家切到 0.113 后缺少 22 张默认排除。隐藏卡不进入当前版本的可见分组，也不进入排除索引。

设置架构版本由 4 升到 5。旧档首次启动整份重置为上述默认集合。旧字段 `Groups` 与 `Exemptions` 不再读取。

## 备选方案

**保留 `Groups` 与 `Exemptions` 两层，增加同步写入。** 否决。两层仍然是两个真相来源。任何新入口，例如重置、导入、旧档迁移或未来的批量操作，都可能只写其中一层。用户报告的正是这种分歧。

**分组开关保持独立，只在豁免页之间同步卡牌。** 否决。这是 0.0.12 的实现。它只能保证豁免页之间一致，不能保证分组开关与卡牌实际状态一致。

**分组开关读取「全部成员都排除」。** 否决。默认豁免会让多个默认勾选的分组显示为关。例如召唤组默认排除 8 张中的 6 张，开关会显示为关，玩家会误以为该组未生效。读取「至少一张排除」能保持默认状态与现有行为一致。

**把分组开关改成两个按钮「全部排除」「全部保留」。** 否决。按钮能消除混合状态，但会改变用户已经熟悉的开关形态，并增加界面行数。当前方案保留开关，用 `x/y` 说明行表达混合状态。

**按版本分别计算默认集合，0.111 只存可见卡。** 否决。同一份设置文件会在玩家切换游戏版本后缺少愚者卡的默认状态，0.113 上这些卡会被错误保留。默认集合必须覆盖 `CardGroups.All`。

## 后果

获益：

- 一张卡只有一个筛选状态。分组页、豁免页、排除索引与实际发牌都读同一个集合。
- 跨组卡不再可能出现「这组保留、那组排除」。
- 分组开关与豁免开关的改动通过同一父绑定刷新，不需要额外的同步代码。
- UI 不再保存分组布尔值，减少一类可以与实际状态脱节的字段。

代价：

- 分组开关是批量命令，不是独立策略。关闭一个分组会保留它的全部成员，包括该组里原本单独排除的卡；再打开会排除全部成员，包括原本单独豁免的卡。
- 分组开关只能表达「是否有牌被排除」，不能表达「全部排除」。混合状态靠说明行的 `x/y` 表达。
- `Filtered` 保存的是全量卡牌状态。默认集合含隐藏卡，0.111 的设置文件会大于当前可见名单。
- 设置架构版本升到 5，旧档的自定义分组与豁免状态被重置。

下游必须遵守的规则：

1. 不得新增按分组存储的筛选布尔值。分组状态只能从 `Filtered` 派生。
2. 读取某卡状态时只查卡牌标识，不得按分组拼接键。
3. 分组开关写入必须原子地改写全组成员，不得逐张触发多次存档。
4. 设置页的分组说明必须显示由 `Filtered` 算出的 `x/y`，不得显示静态张数代替状态。
5. 新增跨组卡时，默认集合按「任一默认勾选分组包含它」计算，显式默认豁免优先。
6. 实际发牌仍受总开关、判定模式、本职业卡池门控与空结果回退覆盖；这些是作用域覆盖，不是第二份卡牌状态。规则见 SP-020、SP-005、SP-004 与 SP-002。
