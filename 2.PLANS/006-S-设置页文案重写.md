## 一、问题

用户原话：「我们的设置页的文本有点反人类且难以看懂，你看着优化一下，中英都要。」

按用户实际看到的界面逐行读，问题分六类。

| 序 | 问题 | 举例 |
|---|---|---|
| 1 | 开关名只有名词，看不出开关的含义 | 「奥斯提牌」旁一个开关，读完不知道勾上会发生什么 |
| 2 | 说明句写机制定义，不回答「它为什么出现在这里」 | 「通过奥斯提战斗的牌。」 |
| 3 | 名称自带括号与内部术语 | 「充能球牌（含激发、球位）」 |
| 4 | 选项用了实现层词汇 | 「只在棱彩宝石加宽本次发牌时生效」 |

## 三、界面字号的实测约束

`ModSettingsGameSettingsEntryLine.CreateVanillaGeneralSettingsRowLabel` 用字号 28、
最小 18、单行自动缩放；`RitsuControlFactory.CreateInlineDescription` 的说明行是字号 16。
据此定字数上限：

| 位置 | 上限 | 理由 |
|---|---|---|
| 开关名 | 18 字 | 单行，超长会缩到 18 号，再长就挤 |
| 说明行 | 24 字 | 字号 16，单行可读的下限，超过会换行占高度 |
| 页说明 | 60 字 | 页头允许换行 |
| 节说明 | 30 字 | 节头允许换行 |

## 四、文案对照

### 4.1 总开关

| 键 | 旧 | 新 |
|---|---|---|
| `pgf.master.desc` | 关闭后，卡牌奖励与游戏原本生成的完全一致。 | 关掉后和没装本模组一样。 |
| `pgf.mode.name` | 生效时机 | 过滤时机 |
| `pgf.mode.desc` | 默认取值与棱彩宝石自身的作用范围一致。 | 不确定就保持默认。 |
| `pgf.mode.gem` | 只在棱彩宝石加宽本次发牌时生效 | 只在棱彩宝石起作用时过滤 |
| `pgf.mode.any` | 只要候选里出现其他职业的牌就生效 | 奖励里出现别的职业牌就过滤 |

### 4.2 分组开关

开关名 = `pgf.exclude.prefix`（排除）+ `pgf.group.<id>.name`。
说明 = `pgf.group.<id>.desc` + 分隔符 + `pgf.count`（如「14 张」）。

| 分组 | 新名称 | 新说明 |
|---|---|---|
| osty | 奥斯提牌 | 靠奥斯提战斗 |
| summon | 召唤牌 | 召唤或强化奥斯提 |
| doom | 灾厄牌 | 施加或消耗灾厄 |
| orb | 充能球牌 | 生成、激发充能球，或增加栏位 |
| focus | 集中牌 | 获得或施加集中 |
| sly | 奇巧牌 | 带奇巧关键字 |
| shiv | 小刀牌 | 生成或强化小刀 |
| poison | 中毒牌 | 施加或消耗中毒 |
| forge | 铸造牌 | 铸造，强化君王之剑 |
| star | 辉星牌 | 消耗或产生辉星 |
| arrow | 箭矢牌 | 发射箭矢 |
| impale | 扎穿牌 | 施加或消耗扎穿 |
| multiplayer | 多人专属牌 | 只在多人模式中出现 |

## 六、偏差

- 计划里写「分组说明改为短句」，实施时补了两件计划外的事：说明后面拼上名单张数（顺手满足 SP-028），以及开关标题也改为拼装而非纯名词。两件都属于同一目标，未单独建计划。
- 计划里预计术语偏差 12 处，实施时逐一对照后确认就是 12 处，另加「联机对局 → 多人模式」1 处，合计 13 处改动。
- 计划没有预料到简体与繁体的机制名差异这么大。繁体有 4 处与简体不同（惡兆、貫穿、縛亡者、寂靜獵手），不能按简体逐字转写。这条已写进 `3.DOCS` 的失败经验。
