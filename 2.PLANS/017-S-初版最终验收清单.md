## 2. 通用准备

### 2.1 环境

1. 游戏版本为 `0.113.1`。
   - 主菜单或无头日志应出现 `Release Version: v0.113.1`。
2. 模组版本为 `0.0.15`。
   - 设置页或模组列表显示 `0.0.15`。
3. RitsuLib 已安装且版本不低于 `0.6.14`。
4. 测试门 `mods/AutoSlayGate` 不存在。
   - 当前已移出。若发现它存在，先报告，不要继续验收。
5. 当前设置以 schema 7 为准。
   - 12 个分组开启。
   - 4 个分组关闭：小刀牌、中毒牌、箭矢牌、多人专属牌。
   - 13 条默认豁免。

### 2.2 建议先备份

复制设置文件：

```text
%APPDATA%\SlayTheSpire2\steam\76561198869461680\mod_data\PrismaticGemFilter\settings.json
```

保存到项目 `TMP/` 下，并记录复制时间。

验收会改动开关与豁免。完成后按备份恢复，或明确接受当前设置。

### 2.3 记录方式

每项记录四项：

1. 状态：通过、失败、跳过、阻塞。
2. 操作步骤编号。
3. 截图或日志路径。
4. 偏差说明。

失败时记录卡牌中文名与英文名。只写“看起来不对”无法定位。

## 3. A1：0.113.1 设置页

### 3.1 目的

确认 `0.113.1` 下设置页结构完整、数字正确、交互同步、三语可用、重启后保持。

### 3.2 前置条件

- 游戏 `0.113.1`。
- 不安装测试门。
- 使用当前默认设置。
- 设置页入口：游戏主菜单 → 设置 → 模组 → 棱彩宝石过滤。

### 3.3 页面结构

#### 检查 A1-1：分组总数

预期：

- 共 16 个分组。
- 共 17 个页面。
- 页面数由 1 个主页面和 16 个分组豁免子页组成。

分组清单：

| 分节 | 分组 |
|---|---|
| 亡灵契约师 | 奥斯提攻击牌、召唤牌、灾厄牌、灵魂牌 |
| 故障机器人 | 充能球牌、集中牌 |
| 静默猎手 | 奇巧牌、小刀牌、中毒牌 |
| 储君 | 铸造牌、辉星牌 |
| 愚者 | 箭矢牌、扎穿牌、悲伤相关牌 |
| 其他 | 多人专属牌、现版本有 bug 的牌 |

判定：

- 16 个开关全部存在。
- 每个开关都有独立豁免子页。
- 没有空白分节或重复分节。

#### 检查 A1-2：愚者内容全量显示

`0.113.1` 应显示：

- 愚者分节。
- 箭矢牌。
- 扎穿牌。
- 悲伤相关牌。
- 现版本有 bug 的牌。
- 多人专属牌中的「火力掩护」。

判定：

- 上述内容全部可见。
- 不出现“版本不支持”或“已隐藏”的提示。

#### 检查 A1-3：默认开关状态

预期：

- 开启：奥斯提攻击牌、召唤牌、灾厄牌、灵魂牌、充能球牌、集中牌、奇巧牌、铸造牌、辉星牌、扎穿牌、悲伤相关牌、现版本有 bug 的牌。
- 关闭：小刀牌、中毒牌、箭矢牌、多人专属牌。

判定：

- 12 个开关开启，4 个关闭。
- 与当前设置一致。

#### 检查 A1-4：组说明的 `x/y`

主行格式：

```text
本组过滤：x/y
```

`y` 是本组成员数。`x` 是本组开关自身贡献的过滤数。

当前默认值：

| 分组 | 预期主行 |
|---|---|
| 奥斯提攻击牌 | 11/11 |
| 召唤牌 | 6/8 |
| 灾厄牌 | 12/14 |
| 灵魂牌 | 6/9 |
| 充能球牌 | 23/25 |
| 集中牌 | 4/5 |
| 奇巧牌 | 9/9 |
| 小刀牌 | 关闭时 0/12 |
| 中毒牌 | 关闭时 0/12 |
| 铸造牌 | 10/11 |
| 辉星牌 | 25/27 |
| 箭矢牌 | 关闭时 0/13 |
| 扎穿牌 | 10/10 |
| 悲伤相关牌 | 11/12 |
| 多人专属牌 | 关闭时 0/12 |
| 现版本有 bug 的牌 | 1/1 |

判定：

- 数字与上表一致。
- `x/y` 不是写死的文案，切换开关后会变化。
- 关闭组的主行固定为 `0/y`。

#### 检查 A1-5：跨组第二行

条件：关闭「召唤牌」，保持「灵魂牌」开启。

预期：

- 召唤牌主行为 `0/8`。
- 第二行出现「在其他组仍被过滤：1/8」。
- 第二行的 1 是 `DIRGE`（挽歌）。

原因：`DIRGE` 同时属于召唤牌与灵魂牌。召唤组关闭后，灵魂组仍会过滤它。

恢复：

- 重新开启召唤牌。
- 第二行应消失。

判定：

- 第二行只在跨组卡仍被其他开启组过滤时出现。
- 数字为 `1/8`。
- 恢复后不残留旧文案。

#### 检查 A1-6：跨组豁免同步

目的：同一张牌的豁免状态跨组共享。

步骤：

1. 打开「铸造牌」子页。
2. 取消「大爆炸」的豁免。
3. 返回「辉星牌」子页。
4. 观察「大爆炸」的勾选状态。

预期：

- 两个子页的「大爆炸」同时变为未豁免。
- 两个分组的主行计数各增加 1。
- 顶部说明「豁免在分组间共享」与实际一致。

恢复：

1. 任选一个子页，重新勾选「大爆炸」。
2. 另一个子页应同步恢复。
3. 两行计数回到默认值。

判定：

- 两个视图共享同一状态。
- 不出现一个页勾选、另一个页未勾选。
- 恢复后计数回到 `10/11` 与 `25/27`。

#### 检查 A1-7：灵魂牌默认豁免

打开「灵魂牌」子页。

预期：

- 勾选：守墓人、捕捉灵魂、降灵。
- 未勾选：`DEVOUR_LIFE`、`DIRGE`、`HAUNT`、`REAVE`、`SEVERANCE`、`SOUL_STORM`。
- 主行为 `6/9`。
- 3 张豁免牌计入 `y`，不计入 `x`。

判定：

- 3 张默认豁免正确。
- 另外 6 张可被过滤。
- 卡名使用游戏原始文本，不是自行翻译。

#### 检查 A1-8：三语显示

依次切换游戏语言：

1. 简体中文。
2. 繁体中文。
3. English。

每种语言检查：

- 页面标题。
- 16 个分组名。
- 分组说明。
- 豁免页按钮。
- 卡牌名。

预期：

- 没有缺键、`pgf.*` 标识或英文回退混入中文。
- 卡名来自游戏 `cards` 表。
- 英文卡名不是自造翻译。
- 繁体中文使用 `zht` 文案，不自动回退为简体。

判定：

- 三种语言均完整。
- 同一张卡在三个语言下的名称符合游戏原文。

#### 检查 A1-9：开关重启保持

步骤：

1. 任选一个默认关闭的组，例如「小刀牌」。
2. 开启它。
3. 退出游戏到桌面。
4. 重新启动游戏。
5. 打开设置页。

预期：

- 「小刀牌」仍为开启。
- 主行从 `0/12` 变为 `12/12`。
- 其他开关不变。

恢复：

- 把关掉的组恢复为默认关闭。

判定：

- 重启后状态保持。
- 不出现整份设置被重置。

#### 检查 A1-10：跨组卡在过滤时的可见性

条件：默认设置 + 战斗奖励。

预期：

- 不属于本职业、且未豁免的组成员不出现在候选。
- 本职业卡池的牌即使被名单命中也会保留。
- `BIG_BANG` 默认豁免，仍可出现。
- `DIRGE` 未豁免，默认被召唤/灵魂组过滤。

判定：

- 观察奖励候选，不只看最终选牌。
- 需要日志时查看 `[filter]` 行。

## 5. A3：双人多人局

### 5.1 目的

确认多人限定卡不被单人大类误删，多人专属组开关有效，跨职业过滤在双人局仍生效。

### 5.2 前置条件

- 游戏 `0.113.1`。
- 双人联机局。
- 至少一名玩家持有棱彩宝石。
- 默认设置。
- 至少打到一场战斗奖励。
- 多人专属牌默认关闭。

### 5.3 检查项

#### 检查 A3-1：双人局仍过滤

预期：

- 持宝石玩家的战斗奖励出现 `[filter]` 行。
- 其他职业、未被豁免的组牌被排除。
- 本职业牌保留。

判定：

- 过滤不因多人模式关闭。
- 奖励候选不是无限重抽。

#### 检查 A3-2：休眠与引火不被球组误删

「休眠」与「引火」是多人限定球牌。

条件：

- 充能球牌开启。
- 未开启多人专属牌也可以出现这两张。
- 不能因为它们在球组名单外就被错误处理。

预期：

- 两张卡可以出现在奖励候选。
- 不因球组开关被删除。
- 不因多人限制被错误放行或错误过滤。

判定：

- 两张卡至少各见一次。
- 若未出现，记录种子、角色、楼层与奖励内容，不直接判失败。

#### 检查 A3-3：多人专属组开关

步骤：

1. 关闭「多人专属牌」。
2. 打一场战斗，记录奖励候选。
3. 开启「多人专属牌」。
4. 打一场战斗，记录奖励候选。

预期：

- 关闭时，多人组不贡献过滤。
- 开启时，主行从 `0/12` 变为 `12/12`。
- 开启后，彼岸一瞥、灵魂绑定等成员被过滤。
- 火力掩护在 0.113.1 中可见，并属于多人组。

判定：

- 开关前后候选差异符合名单。
- 不出现“开了反而更多他职业牌”的反向结果。

#### 检查 A3-4：彼岸一瞥与灵魂绑定

预期：

- 两张牌只属于多人专属组。
- 单人大类名单不包含它们。
- 多人组关闭时不因其他组被误删。
- 多人组开启后被过滤。

判定：

- 两张牌在多人组子页可见。
- 在 0.111.1 中仍可见。
- 单人模式不出现这两张。

## 8. A5：默认模式边界来源

### 8.1 目的

确认模组只处理「棱彩宝石会加宽本次发牌」的情况，不误伤其他来源。

### 8.2 条件

- 游戏 `0.113.1`。
- 默认模式 `PrismaticGemOnly`。
- 先持宝石测试，再卸下宝石对照。
- 记录每个来源是否出现 `[filter]`。

### 8.3 检查项

#### A5-1 普通商店

预期：

- 商店卡牌不走 `CardCreationOptions`。
- 不出现 `[filter]`。
- 候选不被模组改变。

#### A5-2 普通事件

预期：

- 不满足 `IsCardReward` 的事件发牌不出现 `[filter]`。
- 候选保持原样。

#### A5-3 万花筒

条件：持宝石。

预期：

- 自带 `NoCardPoolModifications`。
- 默认模式不出现 `[filter]`。
- 其他职业牌可以正常出现。

#### A5-4 海玻璃

条件：持宝石。

预期：

- 自带 `NoCardPoolModifications`。
- 默认模式不出现 `[filter]`。
- 指定角色牌正常出现。

#### A5-5 色彩哲学家

条件：持宝石。

预期：

- 自带 `NoCardPoolModifications`。
- 默认模式不出现 `[filter]`。
- 排除名单中的牌可以出现。

历史证据：`CARD.SNAP` 曾在持宝石时出现且无过滤记录。

#### A5-6 角色卡修正器

条件：自定义模式启用 `CharacterCards`，并持宝石。

说明：这一项与前三项不同。`CharacterCards` 自己会给卡牌奖励扩池。

预期：

- 卡牌奖励带 `IsCardReward` 且不带 `NoCardPoolModifications`。
- 默认模式会过滤。
- 不把“有他职业牌”误判为“模组越界”。

判定：

- 商店、事件、万花筒、海玻璃、色彩哲学家：无过滤。
- 角色卡修正器：应当过滤。
- 两者不要混为一谈。

### 8.4 判定
