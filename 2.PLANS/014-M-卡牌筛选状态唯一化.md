- 开始时间：2026-11-18 20:22

- 关联需求：RQ-023（已废止，被 RQ-024 取代）
- 关联决策：[ADR-015](../4.ADR/015-筛选状态按卡牌唯一记录.md)
- 关联规范：SP-031 至 SP-036

## 目标

把设置模型从「分组布尔值 + 卡牌豁免清单」两层，改为「一份按卡牌记录的排除集合」。分组开关与豁免开关都读写同一份集合。这样一张牌只有一个筛选状态，跨组页面、分组开关与实际过滤结果一致。

## 非目标

- 不改变分组成员名单、默认豁免名单与分组默认值。
- 不改变判定模式、总开关、池门控与空结果回退。
- 不引入分组级的三态控件。混合状态用 `x/y` 说明行表达。
- 不迁移 0.0.12 的自定义设置；按 SP-024 整份重置。

## 数据模型

落盘模型只保留一个卡牌集合：

```csharp
internal sealed class SettingsModel
{
    public int SchemaVersion { get; set; }
    public FilterMode Mode { get; set; }
    public bool MasterEnabled { get; set; }
    public List<string>? Filtered { get; set; }
}
```

- `Filtered` 的元素是已排除的卡牌标识。
- `null` 表示从未改过，取默认集合。
- 默认集合：所有默认勾选分组的成员并集，减去 SP-021 的 10 张显式默认豁免。
- 默认集合按 `CardGroups.All` 计算，包含当前游戏版本隐藏的愚者卡。

分组开关：

- `Read`：本组至少一张成员在 `Filtered` 内。
- `Write(true)`：把全组成员加入 `Filtered`。
- `Write(false)`：把全组成员移出 `Filtered`。

卡牌开关：

- `Read`：该卡不在 `Filtered` 内。
- `Write(true)`：把该卡移出 `Filtered`。
- `Write(false)`：把该卡加入 `Filtered`。

分组与卡牌绑定都从同一个 `FilteredBinding` 投影。这样 RitsuLib 的刷新拓扑能把父绑定变更传播到所有页面。

## 验收

- 数据级：单卡在两个分组页读同一状态；分组开关读值为任一张成员排除；分组写入后全组状态一致；默认集合在 0.113 全表为 121 张，0.111 可见部分为 99 张。
- 运行时：0.111.1 无头启动 `schema=5`，设置注册成功，`FilterIndex` 排除数与默认集合一致。
- 运行时：0.111.1 对局内仍出现 `[filter] removed=99`，与 0.0.12 的默认排除数一致。
- 界面：分组开关与豁免页的实际点击同步。此项需用户目视；本轮提供代码路径与数据级证据。

## 风险

- 分组开关关闭会清除该组全部单卡排除状态；重新打开会清除全部单卡豁免状态。这是唯一状态模型的代价，界面说明必须写清。
- 0.111 的默认集合含隐藏愚者卡，设置文件条数大于可见排除数。日志必须同时给出存储条数与索引条数。
- 设置架构版本升到 5，旧档自定义状态被重置。
- RitsuLib 的刷新拓扑依赖投影绑定。若分组绑定不是父绑定的投影，跨页刷新会失效。实现时必须共用 `FilteredBinding`。
