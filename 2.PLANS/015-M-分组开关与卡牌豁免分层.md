# 015-M 分组开关与卡牌豁免分层

- 状态：已完成（2026-11-19 01:41；数据级、无头、默认场景与跨组场景通过；界面观感待用户目视）
- 开始时间：2026-11-19 01:25
- 目标版本：0.0.14

- 关联决策：ADR-016
- 关联规范：SP-031 至 SP-039

## 目标

把设置状态恢复为两个互相独立的数据源：

1. `Groups`：每个分组一个开关，决定该组是否参与过滤。
2. `Exemptions`：每张牌一份全局豁免状态，跨组共享。

实际过滤池由这两个来源计算：

```
Pool = ⋃ 已开启且当前版本可见的分组（成员） − 全局豁免牌
```

分组开关不再改写单卡豁免名单；单卡开关也不改写分组开关。

## 非目标

- 不改变分组成员名单。
- 不改变 10 张显式默认豁免。
- 不改变 11 个默认开启、4 个默认关闭的分组默认值。
- 不改变总开关、判定模式、本职业卡池门控与空结果回退。
- 不新增持久化的第三份过滤池。池只作内存缓存。
- 不迁移 schema 5 的旧设置；按 SP-024 整份重置。

## 数据模型

```csharp
internal sealed class SettingsModel
{
    public int SchemaVersion { get; set; }
    public FilterMode Mode { get; set; }
    public bool MasterEnabled { get; set; }
    public Dictionary<string, bool>? Groups { get; set; }
    public List<string>? Exemptions { get; set; }
}
```

- `Groups` 缺键时取 `CardGroup.DefaultEnabled`。
- `Exemptions` 是裸卡牌标识，元素表示「保留」，不表示分组。
- 默认 `Groups`：15 个分组按 `DefaultEnabled` 填满。
- 默认 `Exemptions`：SP-021 的 10 张牌。
- 默认实际池：默认开启组的成员并集减 10 张默认豁免，当前为 121 张。

## 规则

### 分组开关

- 只写 `Groups[组标识]`。
- 不改 `Exemptions`。
- 关闭时，该组不再向实际池贡献任何牌。
- 打开时，该组所有未豁免成员进入实际池。
- 跨组牌：只要有一个已开启组包含它且它未豁免，它就仍在池中。

### 单卡开关

- 全局唯一，所有包含该卡的组共享同一状态。
- 改为豁免：从实际池移除。
- 改为可过滤：若该卡属于至少一个已开启组，则进入实际池。
- 只属于关闭组的卡：状态保留，但暂不进入实际池。

### 实际池

- 构建时只遍历当前版本可见分组。
- 由 `EnabledGroups` 与 `Exemptions` 重算，不增量维护。
- 构建新集合后一次性发布，避免读取到多步增删的中间状态。
- 设置变化、启动、架构重置、版本切换时都走同一构建入口。

## 界面

分组说明显示本组自身贡献：

```
定义 · 13 张 · 本组过滤 12/13
```

组关闭时：

```
定义 · 13 张 · 本组过滤 0/13
本组仍有 1/13 在其他组被过滤
```

第二行只在「组关闭且组内至少一张牌因其他已开启组进入实际池」时显示。简体中文、繁体中文、英文三份文案同步。

豁免页说明改为「勾选保留，取消可过滤；状态跨组共享；分组开关只决定该组是否过滤」。

## 验收

- 数据级：13 张 1 豁免的组，开启时本组贡献 12/13，关闭时 0/13；跨组未豁免牌在另一组开启时仍被过滤。
- 数据级：分组开关不改变 `Exemptions`；单卡开关不改变 `Groups`。
- 数据级：同一张跨组卡的豁免状态在两个组页面读同一值。
- 运行时：无头启动显示 `schema=6`，默认过滤池 121 张，设置注册无异常。
- 运行时：对局内默认设置仍有过滤；关闭一个组后，该组贡献为 0，但跨组未豁免牌仍因其他组被过滤。
- 界面：分组说明的实际贡献与跨组提示文案需用户目视。
- 双语：三份 JSON 键集合一致，无缺键。

## 风险

- schema 5 的旧设置无法区分「组关闭」与「单卡豁免」，因此整份重置；用户已确认。
- 分组说明的「本组过滤」是设置层贡献，不含总开关、判定模式、本职业卡池门控与空结果回退。
- 跨组提示只说明其他组导致的过滤，不表示本组开关自身生效。
- 实际池每次全量重算。规模为 15 组、180 行，成本可忽略。
