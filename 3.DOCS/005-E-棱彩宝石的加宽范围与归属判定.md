# 005-E 棱彩宝石的加宽范围与归属判定

- 建立时间：2026-11-15 09:02
- 适用：游戏 0.113.1
- 关联：[RQ-003](../1.PRD/001-项目初期需求.md)、[RQ-010](../1.PRD/001-项目初期需求.md)、[RQ-011](../1.PRD/001-项目初期需求.md)、[SP-004](../6.SPEC/001-过滤行为规范.md)、[ADR-005](../4.ADR/005-按卡池判定归属.md)

## 结论摘要

1. 棱彩宝石只能做一件事：把「玩家已解锁角色的全部卡池」并进本次发牌的卡池集合。它不生成牌，也不改随机数。
2. 并集之后，玩家本职业的卡池仍在候选集合里。所以「只筛别的职业」这条约束不能省，否则会误删玩家本来就该拿到的牌。
3. 当时（2026-11-15）的 12 组开关，每组只含一个卡池的牌，且该卡池与组的职业一一对应。因此按职业门控与按卡池门控等价。
4. 新增的第 13 组「多人卡牌」跨 5 个卡池，没有单一职业可对应。门控必须改成按每张卡自己的卡池判定。

## 一、棱彩宝石做了什么

`PrismaticGem.ModifyCardRewardCreationOptions` 位置 `sts2.decompiled.cs:98112`，逻辑是四道早退加一次并集：

| 序 | 判据 | 不满足时 |
|---|---|---|
| 1 | 遗物持有者是本次发牌的玩家 | 原样返回 |
| 2 | 选项没有 `NoCardPoolModifications` 标志 | 原样返回 |
| 3 | 选项带 `IsCardReward` 标志 | 原样返回 |
| 4 | 卡池集合不是全无色池 | 原样返回 |
| 5 | 通过后：`options.WithCardPools(player.UnlockState.CharacterCardPools.Union(options.CardPools))` | — |

第 1 条说明加宽只作用于遗物持有者。双人联机时另一位玩家不受影响，他的发牌仍是本职业。

第 5 条的并集在 `sts2.decompiled.cs:98147`。

### CharacterCardPools 是什么

`sts2.decompiled.cs:7860`：

```
public IEnumerable<CardPoolModel> CharacterCardPools => Characters.Select(c => c.Character.CardPool);
```

`Characters` 是该存档已解锁的角色。因此棱彩宝石只并进已解锁角色的卡池，未解锁角色的牌不会出现。

### 加宽之后还有哪些过滤

并集只是改了卡池集合。候选牌仍要过三道关：

- `GetUnlockedCards(player.UnlockState, player.RunState.CardMultiplayerConstraint)`，位置 `TMP/0.0.1/调研-反编译/game/CardPoolModel.cs:101`。它按解锁状态与多人约束筛选。
- `CardCreationOptions` 自带的 `CardPoolFilter`，位置 `sts2.decompiled.cs:39348`。
- `CardFactory` 里的 `IsAllowedInRun`，位置 `TMP/0.0.1/调研-反编译/game/CardFactory.cs:219`。

所以加宽不会让玩家拿到未解锁的牌，也不会让单人局出现多人卡。

## 二、为什么职业门控不能省

加宽后候选集合的样子：

```
玩家 = 铁甲战士
候选 = 铁甲战士池 ∪ 静默猎手池 ∪ 故障机器人池 ∪ 储君池 ∪ 亡灵契约师池 ∪ 愚者池
```

铁甲战士池就在里面。如果模组只按「灾厄牌」这类标记删牌，删的是标记命中的牌，与卡池无关。今天 12 组里没有铁甲战士的牌，所以误删不会发生。但这个结论依赖「分组永远不越池」这个前提，而前提没有被任何机制保证。

反例：第 13 组就跨了 5 个池。若沿用按职业门控，这一组找不到对应的职业。

## 四、第 13 组「多人卡牌」

2026-11-15 08:56 用户指定 6 张：刀刃交响曲、调制、休眠、锤子时间、骸骨军团、火力掩护。

| 类名 | 卡池 | 是否已在其他组 |
|---|---|---|
| `BladeSymphony` | `SilentCardPool` | 刀牌 |
| `Concoct` | `SilentCardPool` | 毒牌 |
| `Hibernate` | `DefectCardPool` | 球牌 |
| `HammerTime` | `RegentCardPool` | 铸剑牌 |
| `LegionOfBone` | `NecrobinderCardPool` | 召唤牌 |
| `CoveringFire` | `FoolCardPool` | 不在任何组 |

6 张都是 `MultiplayerOnly`。它们分布在 5 个卡池，任何「按职业门控」的写法都会失效。

按卡池门控的结果：

- 静默猎手玩家：不排除刀刃交响曲与调制，排除其余 4 张。
- 故障机器人玩家：不排除休眠，排除其余 5 张。
- 铁甲战士玩家：6 张全排除。

## 五、成本

`CardModel.Pool` 的实现在 `sts2.decompiled.cs:75890`：首次访问时遍历 `ModelDb.AllCardPools`，用 `AllCardIds` 哈希查表定位所属卡池，然后缓存到 `_pool`。

运行时不建议依赖这个属性。分组表在生成时已记下每张卡所属卡池，排除索引可以按玩家卡池分档预计算：

```
排除索引[玩家卡池] = ⋃ 已开启组的成员，且成员卡池 ≠ 玩家卡池
```

按角色数量分档，最多 6 档，每档在首次发牌时建一次。之后每张候选牌仍是一次哈希查表，与豁免的成本模型一致（见 [DOCS/003](003-E-豁免与多人卡取证.md) 第四节）。
