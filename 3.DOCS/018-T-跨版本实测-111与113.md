# 018-T 跨版本实测：0.111.1 与 0.113.1

- 建立时间：2026-11-17 23:46
- 分类：T（任务知识）
- 适用：模组 0.0.10，游戏 0.111.1、0.113.1
- 目的：证明同一份 DLL 在两个受支持版本上都能加载并照常过滤，并记下 0.111.1 上跑自动化测试要走的替代路径

## 一、结论

一份 `PrismaticGemFilter.dll` 在 0.111.1 与 0.113.1 上都能加载、都挂上了补丁、都按同一套判据过滤。DLL 未做任何改动，仍是 0.113.1 程序集编译出来的那一份。

两版本的可观察差异只在卡牌总数：0.111.1 还没有愚者这个角色，名单里 22 张可排除牌在该版本不存在，所以移除数是 100 而不是 122。这是预期内的降级，不是故障。

## 二、两个版本能用的自动化手段不同

| 项 | 0.113.1 | 0.111.1 |
|---|---|---|
| `--scenario` 与 `ScenarioRunner` | 有 | 没有 |
| `--autoslay` 与 `AutoSlayer` | 有 | 有 |
| `AutoSlayer.Start` 参数 | `(seed, mode, logFile)` | `(seed, logFile)` |
| 调试控制台 `DevConsole` | 有 | 有 |
| `RunManager.State` 访问级别 | 公开 | 私有，只有 `DebugOnlyGetState()` |

0.111.1 上没有 `ScenarioRunner`。证据：反编译 0.111.1 的 `sts2.dll` 全文搜 `ScenarioRunner` 为 0 次，搜 `HasArg("scenario")` 为 0 次；对二进制搜字符串 `scenario` 也是 0 次。带 `--scenario` 启动不会报错，游戏在资源预加载完成后停在主界面不动，日志里一条 `[Scenario]` 都没有。

因此 0.111.1 的对局内验证改用机器人开一局：先用测试门模组翻转发行版判定，让 `--autoslay` 生效，再在机器人开局后自动给本地玩家发棱彩宝石。

## 三、0.111.1 用的测试门模组

源码在 `8.TEST/0.0.11/AutoSlayGate111/`，模组标识仍是 `AutoSlayGate`，只在对局内测试时放进游戏 `mods/`。三个补丁，一个注入器：

| 部件 | 目标 | 作用 |
|---|---|---|
| `ReleaseFlagPatch` | `NGame.IsReleaseGame` 后置 | 返回值改成 `false`，游戏才会处理 `--autoslay` |
| `GemInjector` | 无补丁，轮询 | 每 500 毫秒查一次对局是否开始，开始后调 `RelicCmd.Obtain` 给本地玩家发 `PRISMATIC_GEM` |
| `CandidateProbePatch` | `CardCreationOptions.GetPossibleCards` 后置，优先级 300 | 打印过滤之后的候选标识清单 |
| `RewardProbePatch` | `CardFactory.CreateForReward` 后置 | 打印一次奖励真正给出的牌 |

`GemInjector` 用 `RunManager.Instance.DebugOnlyGetState()` 取对局状态，用 `LocalContext.GetMe(state)` 取本地玩家，用 `ModelDb.AllRelics` 查宝石模型。这三个 API 在 0.111.1 上都存在。

对照组开关是环境变量 `GATE_NO_GEM=1`，设了就不注入宝石，其余行为不变。

## 四、实测数据

### 4.1 加载与补丁

| 判据 | 0.111.1 | 0.113.1 |
|---|---|---|
| 游戏版本行 | `Release Version: v0.111.1` | `Release Version: v0.113.1` |
| RitsuLib 选中分支 | `Host=v0.111.1; runtime=0.111.0` | `Host=v0.113.1; runtime=0.113.0` |
| 设置注册 | `groups=11/15 exemptions=8 pages=16` | 同左 |
| 补丁应用 | `1 applied, 0 ignored, 0 failed` | 同左 |
| 就绪行 | `ready. groups=15 entries=178 exemptions=8 schema=2 patches=1/1` | 同左 |

两版本的设置注册行、补丁行、就绪行逐字相同。

### 4.2 对局内过滤

同一套默认设置（总开关开、11 组开、8 条豁免），角色都是铁甲战士。

| 判据 | 0.111.1 | 0.113.1 |
|---|---|---|
| 过滤行 | `candidates=429 removed=100 kept=329 poolGate=0 otherPool=344` | `candidates=599 removed=122 kept=477 poolGate=0 otherPool=514` |
| 本职业卡池 | 85 张 | 85 张 |
| 其他职业卡池合计 | 344 张 | 514 张 |
| 探针最终候选 | 329 张 | 391 张 |
| 一次发牌结果 | `LETHALITY,BEAM_CELL,SKEWER`（三个职业） | `HEADBUTT,GRAVE_WARDEN,TURBO` |

0.113.1 的 477 与 391 之间差 86 张，是另一个模组在本次过滤之后又移除的 `MGR_MOD_CARD_*`，与本模组无关。0.111.1 这轮没有这个差额：探针的 329 张与 `kept` 相等，说明没有别的模组在本次过滤之后再动手，`MGR_MOD_CARD_*` 也没有进入这次候选（候选 429 = 本职业 85 + 其他 4 个职业 344）。

### 4.3 对照组：不持有宝石

同一个种子 `GEM111`，加环境变量 `GATE_NO_GEM=1`。

| 判据 | 数值 |
|---|---|
| 角色 | 铁甲战士 |
| `[filter]` 行 | 0 条 |
| 探针候选 | 85 张，即本职业卡池全部 |
| 发牌结果 | `SECOND_WIND,THUNDERCLAP,HEMOKINESIS`、`ARMAMENTS,INFLAME,BATTLE_TRANCE`、`SHRUG_IT_OFF,TAUNT,BREAKTHROUGH` |

三手奖励全是铁甲战士的牌。持宝石时同一入口给出的是跨职业牌，说明加宽与过滤都按预期工作。

## 五、122 与 100 的差额对上了

名单在默认设置下的可排除牌是 122 张（运行期 `[index] rebuilt ... excluded=122`，两版本相同）。0.111.1 只移除了 100 张，差的 22 张需要解释。

做法：反编译 0.111.1 的 `sts2.dll`，取出所有继承 `CardModel` 的类名，按驼峰转大写下划线得到卡牌标识，再与名单比对。得到 597 个标识。

这个方法自洽性检查：用同一份名单算出可排除 122 张，与运行期日志的 `excluded=122` 相同。

差额的 22 张全部是 0.111.1 没有的牌，按分组列如下：

| 分组 | 张数 | 卡牌标识 |
|---|---|---|
| `impale` | 10 | `BOW_SMACK`、`EPIC_RETRIEVAL`、`EXPLOSIVE_ARROWS`、`KI_HOP`、`NAIL`、`RECALL`、`SERRATED_ARROWS`、`UPROOT`、`WAH_HAMMER`、`WREST` |
| `sadness` | 11 | `ALL_IS_WELL`、`ANGUISH`、`ECSTASY`、`ENNUI`、`GROWTH`、`JEST`、`MOURNING_BLOW`、`PUNCH_OF_JOY`、`RUMMAGE`、`SORROWFUL_STRIKE`、`VITRIOL` |
| `bugged` | 1 | `BLOT_OUT_THE_SKY` |

122 − 22 = 100，与 0.111.1 的 `removed=100` 相等。0.113.1 上 122 张全部存在，`removed=122`，同样相等。

这 22 张都属于愚者的机制牌，而 0.111.1 没有愚者角色。0.111.1 的卡牌类共 597 个（其中 1 个是测试用的 `MOCK_CARD_MODEL`），0.113.1 的卡牌索引有 745 条，差 148 张，量级与「新增一个角色」一致。

## 六、版本内容的其他差异

- 0.111.1 的保留集合里有中毒 12 张、小刀 12 张、充能球 2 张、厄运 1 张、集中 1 张、辉星 2 张，与默认豁免逐条对应。
- 0.113.1 的保留集合多出箭矢 13 张与悲伤 1 张（`BRIGHTEN_UP`），0.111.1 上这两个分组没有可保留的牌，因为牌本身不存在。
- 两个版本的保留集合里都没有本模组该排除的分组，逐组核对通过。

## 七、踩到的坑

1. **`--scenario` 在 0.111.1 上静默失效。** 不报错，不提示，游戏停在主界面。判断方法：日志里搜不到 `[Scenario]` 行。
2. **`RunManager.State` 在 0.111.1 上是私有属性。** 编译报 `CS1061`。改用公开的 `DebugOnlyGetState()`。
3. **机器人开局的角色由种子决定。** 种子 `GEM111` 是铁甲战士，种子 `GEM112` 是第三方模组的角色。做对照必须同种子，否则角色不同，候选池没有可比性。
4. **csproj 的 XML 注释不能出现两个连续连字符。** 注释里写了启动参数名就会报 `MSB4025`。
5. **先落地再回看。** 首次 0.111.1 启动日志已被后续启动轮转覆盖，加载证据要从带 `ready.` 行的完整日志里取，所以每轮启动后先把日志复制到 `8.TEST` 再跑下一轮。

## 八、复现步骤

```bash
# 1 部署测试门模组
cd 8.TEST/0.0.11/AutoSlayGate111
dotnet build AutoSlayGate.csproj -c Release
cp bin/Release/AutoSlayGate.dll mod_manifest.json "<游戏目录>/mods/AutoSlayGate/"

# 2 持宝石跑一局
cd "<游戏目录>"
SteamAppId=2868840 ./SlayTheSpire2.exe --headless --autoslay --seed=GEM111

# 3 对照组：不注入宝石
GATE_NO_GEM=1 SteamAppId=2868840 ./SlayTheSpire2.exe --headless --autoslay --seed=GEM111

# 4 收工
taskkill //F //IM SlayTheSpire2.exe
```

日志在 `%APPDATA%\SlayTheSpire2\logs\godot.log`，每次启动轮转。看到目标行后先复制留档，再结束进程。

测试完成后必须把 `mods/AutoSlayGate` 移入回收站，否则该模组会继续翻转发行版判定。

## 九、能证明与不能证明

能证明：

- 同一份 DLL 在两个版本上都加载成功，补丁 1 应用 0 失败。
- 持宝石时两个版本都触发了过滤，移除数与名单、与版本卡牌集合三方一致。
- 不持宝石时 0.111.1 不过滤，候选就是本职业卡池 85 张。
- 宝石加宽在 0.111.1 上生效，一次奖励可以给出三个职业的牌。

不能证明：

- 0.111.1 上的遗物发牌入口（星系仪、遗失宝箱、玻璃眼、祈祷轮、白星、梦境捕手）。这些入口在 0.113.1 上用场景脚本验过，0.111.1 没有场景脚本，调试控制台命令需要自己驱动，本轮未做。
- 0.111.1 上的界面渲染与设置页交互。
- 0.111.1 上与多人对局相关的行为。
- `min_game_version` 对 0.107.1 的拦截效果。本机没有 0.107.1 的安装。
