## A9 正常过滤

### 命令

```bash
SteamAppId=2868840 GATE_A9=1 ./SlayTheSpire2.exe --headless \
  --scenario=.../8.TEST/0.0.15/A9-113.txt \
  --seed=A9GEM113 --fast-mode=Fast
```

### 结果

| 检查 | 结果 |
|---|---|
| 退出码 | 0 |
| 用时 | 53.75 秒 |
| 过滤 | 3 条 `candidates=678 removed=126 kept=552` |
| 随机数 | 3 条 `[rng]`，计数 `4→4`、`7→7`、`10→10`，`delta=0` |
| 索引 | 1 次重建 |
| 缓存 | `cached_reference=True`；10,000 次 `FilterIndex.Get` 平均 573.5 ns（含反射） |
| 单次过滤 | 10,000 次 `CardFilter.Apply` 平均 69.23 µs（含反射，466 张候选） |
| 端到端 | `getpossible_us=6480.4`、`1060.6`、`1003.9` |
| 结束行 | `Scenario completed successfully: A9-113` |

首次 `getpossible_us` 包含首次调用开销。后两次约为 1 ms。端到端数值包含候选枚举与过滤，不能当作单次过滤耗时。

### 对 SP-010 的结论

`FilterIndex.Get` 在 10,000 次调用中返回同一对象，索引只重建 1 次。运行期没有重复求值。单次过滤耗时 69.23 µs 是含反射调用的上限；它高于 `3.DOCS/003-E` 的 22 µs 旧估算，但数量级相同。

## 首次空候选尝试的失败

- 文件：`A9-113-empty-godot.log`。
- 现象：没有 `[filter]`，候选仍为 592 张。
- 原因：测试门用 `CardFilter.Apply` 的 prefix 跳过原方法。`out Stats` 未初始化，`stats.Removed` 为 0。模组的后置补丁先走「无需过滤」分支，没有进入 `kept.Count == 0`。
- 修复：改为 postfix，先让原方法计算真实统计，再把返回值替换为空列表。复测文件为 `A9-113-empty2-godot.log`。
- 结论：这是测试门缺陷，不是模组缺陷。不能把首次日志当作 SP-002 的证据。
