## 补丁点与调用链

补丁打在 `CardCreationOptions.GetPossibleCards(Player)` 上，理由见 [ADR-001](../4.ADR/001-在候选牌枚举处统一过滤.md)。三版签名一致：

| 版本 | 文件:行 | 声明 |
|---|---|---|
| 0.107.1 | `CardCreationOptions.cs:169` | `public IEnumerable<CardModel> GetPossibleCards(Player player)` |
| 0.111 | `CardCreationOptions.cs:134` | 同上 |
| 0.113.1 | `CardCreationOptions.cs:134` | 同上 |

三版都没有重载，宿主都是 `public record CardCreationOptions`（0.113.1 为第 19 行）。

调用链只有一条主干：

```
功能入口
 ├─ CardFactory.CreateForReward(Player, int, CardCreationOptions)   CardFactory.cs:90
 │    └─ 私有重载                                                  CardFactory.cs:215
 │         ├─ Hook.ModifyCardRewardCreationOptions                 CardFactory.cs:217
 │         └─ options.GetPossibleCards(player)   ← 补丁点          CardFactory.cs:218
 └─ 直接调用 GetPossibleCards
```

两条必须知道的性质：

1. 第 217 行的钩子先于补丁点执行。改卡池的钩子有四处：`PrismaticGem.cs:46`、`CharacterCards.cs:56`、`DingyRug.cs:27`、`BigGameHunter.cs:56`。所以补丁点看到的 `CardPools` 常常已经不是调用方写的那一份。
2. `GetPossibleCards` 返回惰性查询，见 `CardCreationOptions.cs:136-138`。补丁必须自己枚举。
3. `WithCardPools` 是就地改写，见 `CardCreationOptions.cs:144-149`：先 `Clear` 再 `AddRange`，再返回 `this`。

## 战斗内生成：两张能跨职业、但不经过补丁点的牌

| 牌 | 类 | 取牌方式 | 依据 |
|---|---|---|---|
| 飞溅 | `Splash` | 取全部角色卡池、排掉本职业、筛出攻击牌，再抽 3 张 | `Splash.cs:25-33` |
| 恋人 | `TheLovers` | 同样取全部角色卡池排掉本职业，再塞满手牌 | `TheLovers.cs:22-29` |

这两张走的是 `CardPoolModel.GetUnlockedCards` 加 `CardFactory.GetForCombat`，全程不构造 `CardCreationOptions`，因此补丁点一次都不执行。SP-006「不得改变战斗内生成类效果」由结构保证成立，不靠额外判断。

飞溅是无色稀有牌，任何角色都可能拿到。恋人是塔罗 Token，只由愚者的「神话形态」产生，见 `MythicFormPower.cs:37-45`。

## 原版棱彩宝石的作用面

钩子 `ModifyCardRewardCreationOptions` 的调用点只有三处：`CardFactory.cs:217`、`ScrollBoxes.cs:74`、`:76`。分发在 `Hook.cs:1480`。

棱彩宝石的四道早退见 `PrismaticGem.cs:30-45`。能通过的是同时满足三条的选项：带 `IsCardReward`、不带 `NoCardPoolModifications`、卡池不全为无色。

`IsCardReward` 只由 `CardReward` 的第一个构造器补，见 `CardReward.cs:118-119`。所以作用面等于「所有用 `new CardReward(options, 张数, 玩家)` 构造的卡牌奖励」，再减去自带 `NoCardPoolModifications` 的那几个。

| 会被加宽 | 依据 |
|---|---|
| 战斗奖励（普通、精英、首领） | `RewardsSet.cs:231`、`:236`、`:242` |
| 星系仪 | `Orrery.cs:25` |
| 梦境捕手、祈祷轮、白星、猎杀 | `DreamCatcher.cs:22`、`PrayerWheel.cs:24`、`WhiteStar.cs:24`、`TheHunt.cs:47` |
| 遗失宝箱、试炼、水晶球 | `LostCoffer.cs:20`、`Trial.cs:183`、`CrystalSphereCardReward.cs:50` |
| Blitz 模式与它的一批商店条目 | `BlitzRunModel.cs:94`、`:102`、`:112`；`BlitzMerchant*` 七个文件 |
| 读档重建的卡牌奖励 | `Reward.cs:184` |
| 持久糖果 | 不自己加宽，读到的上游池已被加宽，见 `LastingCandy.cs:125` |

| 不会被加宽 | 原因 |
|---|---|
| 万花筒、海玻璃、色彩哲学家、血色脑蛭、药剂未来 | 自带 `NoCardPoolModifications` |
| 卷轴箱 | 钩子跑了，但选项没有 `IsCardReward` |
| 精神错乱、专精、全明星 | 没有 `IsCardReward`；全明星的池还全是无色 |
| 垃圾堆 | 不构造 `CardCreationOptions` |
| 普通商店 | 走 `CreateForMerchant`，不走这个钩子 |
| 飞溅、恋人 | 战斗内生成，同上 |

一句话：原版里，棱彩宝石只作用于「卡牌奖励」这一种形态，其余跨界来源它一概碰不到。

### 三版本差异

`PrismaticGem.cs` 在三个版本上不是同一份：

| 版本 | 行数 | 早退条数 | 差异 |
|---|---|---|---|
| 0.107.1 | 53 | 5 | 多一条 `options.CustomCardPool != null` |
| 0.111 | 48 | 4 | 与 0.113.1 的 SHA-256 相同 |
| 0.113.1 | 48 | 4 | 基准 |

0.107.1 的第五条可以用「选项的卡池为空」等价表达。依据：0.107.1 的 `CardCreationOptions.cs:90-96` 里自定义池构造器不填 `_cardPools`，`:192` 的 `WithCustomPool` 清空卡池，`:206` 的 `WithCardPools` 置空 `CustomCardPool`，`:171` 在卡池为空时改用自定义池。0.111 起 `CustomCardPool` 属性已被移除。

两个 `CardCreationFlags` 枚举值三版一致：`NoCardPoolModifications = 0x10`、`IsCardReward = 0x80`。0.111 起新增 `IsFromCombat = 0x100`，与本模组无关。

## 结论

1. 补丁点只有一个，但功能入口有 24 个。补丁是「全域拦截」，不是「只拦战斗奖励」。
2. 真正能在候选里出现他职业牌的来源只有五条：棱彩宝石扩池、角色卡修正器 `CharacterCards` 扩池、万花筒、海玻璃、色彩哲学家。前两条走同一段钩子代码，后三条各自把别的职业池直接写进 `options`。
3. 用户列出的五个来源中，垃圾堆事件是唯一不经过补丁点的。万花筒、海玻璃、色彩哲学家、自定义模式（`CharacterCards`）都经过。
4. 按 0.0.2 的实现（不读遗物），这四条来源在不持有棱彩宝石时也会被排除名单内的牌。这与 RQ-005 冲突。证据与判定见 [009-E](009-E-对局内过滤实测.md) 的「棱彩宝石的来源与判定方式」一节。
5. 游戏里能拿到他职业牌的来源不止四条。除补丁点覆盖的那四条，还有垃圾堆（直接造牌）、飞溅与恋人（战斗内生成）三条。后三条都不经过补丁点，本模组碰不到它们。
6. 原版棱彩宝石只加宽「卡牌奖励」这一类。它不碰万花筒、海玻璃、色彩哲学家、垃圾堆、普通商店、飞溅与恋人。所以「持有棱彩宝石」与「候选被棱彩宝石加宽」在原版里是两件不同范围的事：前者是后者的必要条件，不是充分条件。
