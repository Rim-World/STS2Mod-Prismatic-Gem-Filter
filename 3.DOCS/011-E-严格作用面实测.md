# 011-E 严格作用面实测

- 时间：2026-11-15 22:27
- 用途：验证 0.0.3 的默认判据是否只作用于原版棱彩宝石的作用面，以及设置取值能否跨重启保持
- 数据来源：两份游戏日志，见 `8.TEST/0.0.3/`
- 相关条款：SP-005、SP-017、SP-018、SP-019

## 测试方法

用开发者控制台直接触发事件，省去走路的时间：

```
event COLORFUL_PHILOSOPHERS
```

色彩哲学家是本次的判别点。它的候选来自单个他职业卡池，且选项自带 `NoCardPoolModifications`，见 `ColorfulPhilosophers.cs:57-59`。按 `4.ADR/008` 的五条判据，原版棱彩宝石不会加宽它，本模组也不该排除它。

对照项是战斗奖励：同样的玩家、同样的职业，宝石在场时它会被加宽，本模组应排除名单内的牌。

## 情形一：持有宝石，战斗奖励

来源：`user-playtest-colorful-philosophers-godot.log`，第 1487 至 1860 行。

| 项 | 值 |
|---|---|
| 玩家 | 静默猎手 |
| 模组版本 | 0.0.3 |
| 启动时的模式 | `PrismaticGemOnly` |
| 过滤调用次数 | 27 次 |

27 次调用分成 9 组，每组 3 次，对应 9 次战斗奖励各 3 张牌。每次的统计完全一致：

```
mode=PrismaticGemOnly candidates=513 removed=12 kept=501 poolGate=0 otherPool=427
```

| 字段 | 含义 | 结论 |
|---|---|---|
| `candidates=513` | 加宽后的全部候选 | 与 `3.DOCS/010-E` 的估算吻合 |
| `removed=12` | 排除张数 | 与排除名单的 12 张相等，说明整组都在候选里 |
| `poolGate=0` | 池门控放行张数 | 静默猎手卡池里没有奥斯提牌，符合预期 |
| `otherPool=427` | 候选里他职业牌张数 | 大于 0，说明宝石确实加宽了 |

这与 0.0.2 时期的实测数字一致，见 `3.DOCS/009-E`。判定改了判据，结果没变。

## 情形二：持有宝石，色彩哲学家

来源：同一份日志，第 1955 至 1970 行。

| 项 | 值 |
|---|---|
| 触发方式 | `event COLORFUL_PHILOSOPHERS` |
| 当时是否持有宝石 | 持有。卸下宝石的命令在第 1972 行，晚于本事件 |
| 事件发出的牌 | `CARD.TRANSFIGURE`、`CARD.CLEANSE`、`CARD.SNAP` |
| 本模组的过滤记录 | 无 |

关键点是 `CARD.SNAP`。它在排除名单里，属于奥斯提攻击牌，而玩家是静默猎手。按 0.0.2 的判据，这张牌会被删；0.0.3 保留它，因为原版棱彩宝石并不加宽色彩哲学家。

也就是说：**手里拿着宝石，模组也没有动色彩哲学家发出的牌。** 这是严格作用面的直接证据。

## 情形三：卸下宝石，色彩哲学家

来源：同一份日志，第 1972 至 1986 行。

| 项 | 值 |
|---|---|
| 前置命令 | `relic remove PRISMATIC_GEM`，第 1972 行 |
| 触发方式 | `event COLORFUL_PHILOSOPHERS`，第 1973 行 |
| 事件发出的牌 | `CARD.SQUEEZE`、`CARD.FRIENDSHIP`、`CARD.SCOURGE` |
| 本模组的过滤记录 | 无 |

`CARD.SQUEEZE` 也在排除名单里。没有宝石时它照常出现，符合 SP-005。

第 1900 行之后没有任何 `[filter]` 行，两次事件都没有触发过滤。

## 情形四：改设置后重启

来源：`user-restart-mode-persisted-godot.log`，第 460 行。

用户把判定模式改成第二个取值，完全退出游戏，再启动。

| 项 | 值 |
|---|---|
| 新会话启动日志 | `[settings] registered. mode=AnyWidenedPool` |
| 设置文件 | `{"Mode": 1}` |
| 本次会话的过滤调用 | 0 次（只是启动并查看设置，没有取奖励） |

说明取值确实落在磁盘上、跨进程生效。符合 SP-018。

## 结论

| 结论 | 状态 | 依据 |
|---|---|---|
| 持有宝石时战斗奖励照常排除 12 张 | 已验证 | 27 次调用，`removed=12` |
| 持有宝石时色彩哲学家不被排除 | 已验证 | `CARD.SNAP` 被发出，无过滤记录 |
| 不持有宝石时色彩哲学家不被排除 | 已验证 | `CARD.SQUEEZE` 被发出，无过滤记录 |
| 判定模式跨重启保持 | 已验证 | 重启后 `mode=AnyWidenedPool`，文件为 `{"Mode": 1}` |
| 第二个取值的实际过滤效果 | 未验证 | 重启后没有取过奖励，`[filter]` 为 0 行 |

## 异常

日志里有 2 行 `[ERROR]`，第 1368 与 1392 行：

```
System.InvalidOperationException: NSpineAutoPlayer's parent's skeleton data must have exactly 1 animation. This has 6.
```

这是骨骼动画相关的报错，来自某个动画模组，与本模组无关。本模组没有任何 `[filter] failed`、`filter abandoned` 或 `[ERROR]`。

## 待确认

- 第二个取值是否真的会过滤色彩哲学家。确认方法：当前设置已经是 `AnyWidenedPool`，再执行一次 `event COLORFUL_PHILOSOPHERS`，日志应出现 `mode=AnyWidenedPool` 且 `removed` 大于 0。这一条同时能证明补丁确实覆盖了色彩哲学家的发牌路径，而不只是「没有记录」。
- 遗物发牌（星系仪一类）的过滤仍未实测。确认方法：用控制台 `relic add ORRERY` 并取奖励。
