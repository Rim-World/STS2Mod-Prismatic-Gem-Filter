# 003-E 大类内豁免与多人限定卡的取证

- 建立时间：2026-11-15 07:12
- 适用：游戏 0.113.1，对照 0.107.1 与 0.111.0 的卡牌索引
- 关联：[RQ-009](../1.PRD/001-项目初期需求.md)、[RQ-010](../1.PRD/001-项目初期需求.md)、[SP-013](../6.SPEC/001-过滤行为规范.md)、[SP-014](../6.SPEC/001-过滤行为规范.md)、[ADR-004](../4.ADR/004-豁免在构建索引时扣除.md)

## 结论摘要

1. 大类内豁免不迫使运行时穷举。豁免在建立过滤索引时一次性扣除，运行时仍是每张候选牌一次哈希查表。
2. 实测：索引就绪后单次过滤 11.40 µs（无豁免）对 10.91 µs（含豁免），差异在噪声内。索引构建多花 4.30 µs，只在设置变更时发生一次。
3. 对照的朴素写法（每张候选牌逐个大类、再逐条比对豁免表）耗时 209.31 µs，是建议设计的 8.2 倍。
4. 用户点名的 5 张卡在 0.107.1、0.111.0、0.113.1 三个版本都存在，中文名一致。
5. `BigBang` 同时属于铸剑与星两类，`TheSmith` 同样。豁免必须按大类分别记录，否则两类的开关会互相抵消。
6. 0.113.1 共有 43 张 `MultiplayerConstraint == MultiplayerOnly` 的卡牌，其中 9 张落在 12 个可筛大类内。不做保护时，多人模式开启「球牌」会连带屏蔽「休眠」「引火」。

## 二、一门多组的卡

12 个大类合计 178 行，去重后 176 张。重复的只有两张，且都是「铸剑 + 星」：

| 类名 | 中文名 | 所属大类 |
|---|---|---|
| `BigBang` | 大爆炸 | 铸剑牌 + 星牌 |
| `TheSmith` | 铸剑者 | 铸剑牌 + 星牌 |

后果：若豁免只在铸剑侧记录，「星牌」开关打开时 `BigBang` 仍会被排除。若豁免求值改成「先并入所有开启大类的卡、再统一扣除豁免」，则铸剑侧的豁免会误放行星牌侧，语义随求值顺序变化。两种错误都来自把豁免当成全局集合处理。

## 三、多人限定卡的机制

### 3.1 标记与过滤点

- `CardMultiplayerConstraint` 有三个值：`None`、`MultiplayerOnly`、`SingleplayerOnly`。位置 `sts2.decompiled.cs:197279`。
- `CardModel.MultiplayerConstraint` 默认 `None`，卡牌可覆写。位置 `TMP/0.0.1/调研-反编译/game/CardModel.cs:355`。
- 过滤发生在卡池枚举阶段。`CardPoolModel.GetUnlockedCards` 按本次对局的约束删掉相反的一侧，位置 `TMP/0.0.1/调研-反编译/game/CardPoolModel.cs:101`。
- 约束来自对局人数。`IRunState.CardMultiplayerConstraint` 在 `Players.Count <= 1` 时返回 `SingleplayerOnly`，否则返回 `MultiplayerOnly`。位置 `sts2.decompiled.cs:39859`。
- 发牌候选集合的求值入口 `CardCreationOptions.GetPossibleCards` 调用的正是 `GetUnlockedCards(player.UnlockState, player.RunState.CardMultiplayerConstraint)`。位置 `sts2.decompiled.cs:39348`。

### 3.2 与棱彩宝石的关系

`PrismaticGem.ModifyCardRewardCreationOptions` 把 `player.UnlockState.CharacterCardPools` 与原有卡池求并集（位置 `sts2.decompiled.cs:98112`）。并集之后仍逐个卡池调用 `GetUnlockedCards`，因此多人限定卡会照常带入，单人限定卡会照常剔除。这一点不需要模组介入。

`CardFactory.CreateForReward` 在取候选之前调用 `Hook.ModifyCardRewardCreationOptions`（位置 `TMP/0.0.1/调研-反编译/game/CardFactory.cs:217`）。遗物 `Orrery` 构造 `CardCreationOptions` 后交给 `CardReward`，最终也走这条路径（位置 `sts2.decompiled.cs:96419`）。因此棱彩宝石对星系仪的加宽本就存在，过滤点也覆盖两侧。

### 3.3 落在可筛大类里的 9 张

0.113.1 共 43 张 `MultiplayerOnly` 卡牌，下列 9 张同时属于用户要筛选的大类：

| `Hibernate` | 休眠 | 球牌（含激发、球位） | `DefectCardPool` |

## 四、豁免的求值成本实测

### 4.1 方法

在 `TMP/0.0.1/bench-exempt` 建立 .NET 9 控制台工程，读取 `TMP/0.0.1/卡牌名单/卡牌分组名单.csv` 的真实分组数据，构造 718 条候选（176 张唯一卡循环填充，作为候选量的压力上界），12 个大类全部开启，按用户给出的 5 张卡做豁免，并跳过 9 张多人限定卡。四种写法各跑 2000 次取均值，先校验结果集合一致再比时间。

### 4.2 结果

| 写法 | 单次耗时 |
|---|---|
| A 现设计：建索引 + 过滤，无豁免 | 23.69 µs |
| B 建议设计：建索引 + 过滤，含豁免与多人保护 | 25.64 µs |
| C 朴素：每张候选逐个大类、逐条比对豁免 | 209.31 µs |
| D 朴素：豁免表改用 `List` 线性扫描 | 222.47 µs |

拆解：

| 环节 | 无豁免 | 含豁免 |
|---|---|---|
| 索引构建单次 | 10.94 µs | 15.24 µs |
| 索引就绪后单次过滤 | 11.40 µs | 10.91 µs |

- 豁免使索引从 176 项缩到 162 项，运行时查表次数不变，因此过滤耗时不升。
- B、C、D 三种写法的放行结果完全一致，证明提速不来自改变语义。
- 索引只在设置变更后重建一次，构建成本不进入发牌路径。

### 4.3 环境

.NET SDK 9.0.321，`dotnet run -c Release`，单机 Windows。时间含 `Stopwatch` 抖动，量级结论不受影响。
