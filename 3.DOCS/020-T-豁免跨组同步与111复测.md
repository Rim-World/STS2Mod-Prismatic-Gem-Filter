# 020-T 豁免跨组同步与 0.111.1 复测

- 建立时间：2026-11-18 19:57
- 分类：T（任务知识）
- 适用：模组 0.0.12，游戏 0.111.1
- 目的：记录豁免键由分组改为卡牌的原因、暴涨移回球牌组的改动，以及 0.111.1 的实机加载与对局内过滤数据

## 一、用户报告

用户原话：「那些同时出现在两组里的牌，在其中一组关掉并不影响其在另外一组的设置。这个似乎违反了我们的设计要求，显然同一张牌在任何一组里面被过滤或者豁免，状态都应该同步到其他组。」

当时的跨组卡只有两张：

| 卡牌 | 分组 |
|---|---|
| `BIG_BANG`（大爆炸） | 铸造、辉星 |
| `THE_SMITH`（铸剑者） | 铸造、辉星 |

## 二、原因

0.0.4 起豁免键是 `分组标识:卡牌标识`，例如 `forge:BIG_BANG` 与 `star:BIG_BANG`。两个豁免页各自读写自己的键，因此可以出现「铸造组保留、辉星组排除」。这是 ADR-004 当初的明确设计，但与用户现在要求的一致性冲突。

## 三、改动

1. 豁免键改为裸卡牌标识。`ExclusionTable.DefaultExemptionKeys` 与 `SettingsModel.Exemptions` 都只存卡牌标识。
2. `ModSettings.CardBindings` 以卡牌标识为键。同一张跨组卡只创建一个绑定，两个豁免页读同一个绑定对象。
3. `SettingsSnapshot.IsExempt`、`ExclusionTable.IsDefaultExempt` 只接收卡牌标识。
4. 分组开关保持独立。排除条件仍是「至少一个处于勾选状态的可见分组包含该卡，且该卡未被全局豁免」。
5. 设置架构版本由 3 升到 4。旧的分组前缀键全部失效，首次启动整份重置。

默认豁免由 11 条分组键变为 10 张卡：精神过载、血肉戏法、洁净、唤起、聚变、暴涨、大爆炸、汇流、超能光束、活跃气氛。`BIG_BANG` 只记一条。

暴涨同时从集中牌组移回球牌组，仍默认豁免。球牌恢复 25 张，集中牌恢复 5 张。

## 四、0.111.1 实机验证

本机游戏版本为 `v0.111.1`（提交 `cc1f9462`）。同一份 0.0.12 DLL。

### 4.1 无头启动

日志 `8.TEST/0.0.12/自检-0.0.12-111设置注册-godot.log`：

```
[compat] fool=False source=type
[settings] reset. schema 3 -> 4, groups=11/15 exemptions=10
[settings] registered. mode=PrismaticGemOnly master=True groups=8/11 exemptions=10 pages=12
ready. groups=11 entries=143 exemptions=10 schema=4 patches=1/1
```

这组数值同时证明：

- 0.111 隐藏愚者内容：可见分组 11，页面 12。
- 豁免改为按卡牌记录：`exemptions=10`。
- 架构版本已升到 4。
- 可见名单 143 行，等于 180 行减去愚者相关的 37 行。

同一份 DLL 的静态数据检查：

- `defaultKeys=10`，没有任何键包含分组分隔符 `:`。
- 0.113 默认排除数 121，0.111 默认排除数 99。
- 10 条默认键都能在某个分组的成员列表中找到。

### 4.2 对局内过滤

用 `8.TEST/0.0.11/AutoSlayGate111` 翻转发行版判定并注入棱彩宝石，种子 `GEM111`。日志 `8.TEST/0.0.12/自动测试-111-autoslay-0.0.12-godot.log`：

```
[gate] 对局已开始，开始注入棱彩宝石
[gate] 棱彩宝石注入完成
[filter] mode=PrismaticGemOnly groups=8 candidates=429 removed=99 kept=330 poolGate=0 otherPool=344
[filter] mode=PrismaticGemOnly groups=8 candidates=429 removed=99 kept=330 poolGate=0 otherPool=344
[filter] mode=PrismaticGemOnly groups=8 candidates=429 removed=99 kept=330 poolGate=0 otherPool=344
```

`removed=99` 与默认设置的预期值一致：0.111 可见启用组共 110 行，减去跨组重复的「铸剑者」1 条，再减去 10 个豁免成员行（9 张不同卡，大爆炸在铸造与辉星各一行），得 99。愚者组的 `BRIGHTEN_UP` 在 0.111 不可见，因此不计入。

### 4.3 与上一版的差异

| 项 | 0.0.10 | 0.0.11 | 0.0.12 |
|---|---|---|---|
| 游戏版本 | 0.111.1 | 0.113.1 | 0.111.1 |
| `[settings]` | `groups=11/15 exemptions=8 pages=16` | `groups=11/15 exemptions=11 pages=16` | `groups=8/11 exemptions=10 pages=12` |
| `ready.` | `entries=178` | `entries=180` | `entries=143` |
| `[filter]` | `removed=100` | `removed=122` | `removed=99` |

0.0.12 的 `removed=99` 比 0.0.10 的 100 少 1。原因是 0.0.11 把洁净与唤起加入默认豁免，共减少 2 张；钙化加入奥斯提组，增加 1 张；净变化 −1。

## 五、踩到的坑

1. **全局键会让两个页面的绑定必须复用。** 如果仍然在 `BuildBindings` 里逐组创建绑定，后创建的会覆盖先创建的，页面读到的对象可能不是同一个。改为按卡牌标识只创建一次。
2. **默认豁免条数会变少。** 大爆炸由两条分组键合并为一条卡牌键，条数从 11 变成 10，但实际豁免的牌数不变。
3. **0.111 的可见组是 11 个，启用组是 8 个。** 日志里 `groups=8/11` 分别表示「已勾选的可见组」与「可见组总数」，不是 15。
4. **测试门模组必须手动部署。** 它的 csproj 不复制到游戏 `mods/`。测试后要移入回收站，避免影响用户正常游玩。
