# 015-T 无头启动测试方法

- 建立时间：2026-11-16 23:22
- 分类：T（任务知识）
- 适用：本机 Git Bash、游戏 0.113.1、模组 0.0.7
- 首次发现：2026-11-15（记录在 `2.PLANS/002-M-最小工程.md` 第五节），本文补全判据、结束方式与失败对照

## 一、这套方法能证明什么

无头启动用来证明加载链路上的事实。它不开窗口，但加载流程与正常启动相同。

可以证明的项：

- 游戏发现了本模组的清单与程序集，并调用了初始化方法。
- 设置注册成功，分组数、默认勾选数、页面数符合预期。
- 补丁挂在目标方法上，应用结果可读。
- 界面文案按语言取词，取到多少条、有没有回退。
- 名单数据被读进内存，规模与分组数可核对。

不能证明的项：

- 设置页的排版、字号、开关点击与翻页。
- 对局内发牌的实际结果。
- 三种语言中的繁体与英语取词。无头启动读到的是当前游戏语言，本机只有 `zhs`。

## 二、完整流程

### 1. 构建并部署

```bash
cd /c/Users/13167/Desktop/Mod/STS2Mod-优化棱彩宝石
dotnet build 9.SRC/PrismaticGemFilter.csproj -c Release
```

构建目标 `CopyModToGame` 会把 DLL 与清单复制到 `C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\PrismaticGemFilter\`。游戏正在运行时目标文件被占用，构建只给警告，此时先关游戏再构建。

### 2. 启动

```bash
cd "/c/Game/Steam/steamapps/common/Slay the Spire 2"
SteamAppId=2868840 ./SlayTheSpire2.exe --headless
```

三段各自的用途：

| 段 | 用途 |
|---|---|
| `SlayTheSpire2.exe` | 直接运行游戏本体，不经过 Steam 客户端的启动按钮 |
| `SteamAppId=2868840` | 给 Steamworks 提供 AppID。缺了它初始化失败，见第四节 |
| `--headless` | 引擎开关。不开窗口、不渲染，加载流程照常 |

### 3. 等加载完成

判定标志是 `ready.` 行。用循环等待，避免读得太早：

```bash
L="$APPDATA/SlayTheSpire2/logs/godot.log"
for i in $(seq 1 120); do sleep 1; grep -q "ready\. groups=" "$L" && break; done
```

`$APPDATA` 指向 `C:\Users\13167\AppData\Roaming`。`godot.log` 的实际路径是 `%APPDATA%\SlayTheSpire2\logs\godot.log`。

实测耗时：2026-11-16 23:19 用 `date` 差值计时，从进程启动到 `ready.` 行出现为 15 秒。这一次运行完整，日志 671 行、0 行 `[ERROR]`、71,600 字节。

### 4. 结束进程

`--headless` 不会自己退出。加载完成后主循环继续挂着，没有窗口可操作，必须手动结束：

```bash
taskkill //F //IM SlayTheSpire2.exe
```

`//F` 的两个斜杠是 Git Bash 的写法。写成 `/F` 会被当成路径改写，命令收到的是别的参数。

结束前先复制日志，见下一节。

### 5. 留档

游戏每次启动都会轮转覆盖 `godot.log`。所以顺序是：等 `ready.` 行 → 复制日志 → 结束进程。

```bash
cp "$APPDATA/SlayTheSpire2/logs/godot.log" \
   /c/Users/13167/Desktop/Mod/STS2Mod-优化棱彩宝石/8.TEST/0.0.7/自检-0.0.7加载与名单-godot.log
```

复制到 `8.TEST/<版本>/`，并在 `8.TEST/TEST.md` 的版本表里登记文件名、大小与用途。

## 三、AppID 从哪来

本机这四条互相对得上：

| 位置 | 内容 |
|---|---|
| `C:\Game\Steam\steamapps\appmanifest_2868840.acf` | `"appid" "2868840"`、`"name" "Slay the Spire 2"`、`"installdir" "Slay the Spire 2"` |
| 游戏目录 | `C:\Game\Steam\steamapps\common\Slay the Spire 2` |
| 创意工坊目录 | `C:\Game\Steam\steamapps\workshop\content\2868840\3747602295`（RitsuLib） |
| 本次无头启动的日志 | `[INFO] Found release_info.json at: C:\Game\Steam\steamapps\common\Slay the Spire 2\release_info.json` |

游戏目录里没有 `steam_appid.txt`。Steam 客户端启动游戏时会把 AppID 带进去，直接运行 exe 没有这个上下文，所以要自己给。

## 四、缺 AppID 时的现象

2026-11-16 23:18 复现。同一条命令去掉 `SteamAppId` 后，日志第 8 至 10 行是：

```
[INFO] Steamworks: attempting initialization...
[INFO] Steam is running: True
[ERROR] Steamworks initialization failed! Result: k_ESteamAPIInitResult_FailedGeneric, message: No appID found.  Either launch the game from Steam, or put the file steam_appid.txt containing the correct appID in your game folder.
   at MegaCrit.Sts2.Core.Platform.Steam.SteamInitializer.InitializeInternal()
```

这一次日志只有 79 行，完全没有任何模组加载行。所以看到日志很短、又没有 `Found mod manifest file` 时，先查环境变量。

## 五、Steam 客户端必须在线

无头启动不等于脱离 Steam。成功的运行日志里有这两行：

```
[INFO] Steam is running: True
[INFO] Steamworks initialization succeeded!
```

Steam 客户端没登录时后一行不会出现，游戏同样停在这一步。

## 六、读到什么算通过

按要证明的对象查对应的日志行。

| 要证明的 | 日志里的样子 | 0.0.7 的实测值 |
|---|---|---|
| 程序集版本 | `Calling initializer method of type PrismaticGemFilter.Plugin ... Version=0.0.7.0` | `0.0.7.0` |
| 清单被发现 | `Found mod manifest file ...\mods\PrismaticGemFilter\mod_manifest.json` | 命中 |
| 程序集被加载 | `Loading assembly DLL ...\mods\PrismaticGemFilter\PrismaticGemFilter.dll` | 命中 |
| 文案取词 | `[PrismaticGemFilter.texts] Loaded translations: ... entries=64, local=64, fallbackEntries=0` | `64`、`0` 回退 |
| 设置与分组 | `[settings] registered. ... groups=10/14 exemptions=7 pages=15` | `10/14`、`pages=15` |
| 补丁应用 | `Applying 1 patches` → `1 applied, 0 ignored, 0 failed, 1 total` | 1 应用 |
| 名单规模 | `ready. groups=14 entries=166 exemptions=7 schema=1 patches=1/1` | `14` 组、`166` 条 |

`fallbackEntries=0` 表示当前语言没有缺键。若这个数大于 0，说明文案有漏项。

`groups=10/14` 的读法：分母是分组总数，分子是当前生效的勾选数。玩家改过设置时以存档为准，没改过的组取代码默认值。

## 七、常见失败对照

| 现象 | 原因 | 处置 |
|---|---|---|
| 日志约 79 行，含 `No appID found` | 没传 `SteamAppId` | 加环境变量重跑 |
| 日志停在 `Steamworks: attempting initialization...` | Steam 客户端未运行或未登录 | 登录 Steam 后重跑 |
| 日志里有旧版本的模组行 | 读到了上一次启动的日志 | 先看文件时间戳，或等 `ready.` 行 |
| 构建时出现「部署未完成：目标文件被占用」 | 游戏进程还在 | 结束进程后重新构建 |
| 日志里没有 `PrismaticGemFilter` 任何字样 | 模组没被加载 | 查清单文件名、`id` 与 DLL 名是否一致 |
| 进程退不出来，命令一直挂着 | `--headless` 的设计如此 | 前台跑会阻塞；放后台，或另开一个命令 `taskkill` |

最后一条实际踩过：2026-11-16 22:37 第一次无头启动放在前台跑，240 秒后命令仍在运行，工具把它转成后台任务。后来改成先复制日志、再 `taskkill`。
